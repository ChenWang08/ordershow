# 商品分公司与经销商限制

## 业务规则

- 商品列表保留“分公司限制”，新增“经销商限制”。没有任何范围限制时显示“不限制”；存在分公司范围时显示当前有效下单客户数 N 家；指定名单失效时显示待处理。N 是实际有效范围内的客户数，不只是指定名单数量。
- 商品 Excel 支持“分公司限制”表头，兼容“分公司定制品”；空值为全部分公司。图片继续通过独立 ZIP 上传。
- 客户类型为空的商品适用于全部当前有效白名单客户；指定综合/特渠的商品只适用于对应类型。无类型白名单不会越过商品明确指定的客户类型。
- 多分公司按并集；每个分公司默认允许该分公司的全部合格经销商，也可以切换为指定名单。没有指定名单的分公司会动态包含后续新增的合格客户。
- 分公司选中后，经销商复选框默认全部勾选，但这代表“不限制该分公司经销商”，不保存全量客户名单。点击“取消全选”进入指定模式；指定模式必须至少保留一家经销商，保存按钮才可用；点击“恢复全选”删除该分公司的指定名单并回到全部经销商状态。指定模式下手动重新勾选全部客户时，系统归一化为全部状态。
- 不展示或使用大区。经销商以客户类型、标准化分公司、标准化全称区分，权限实际绑定稳定 customer ID 和身份快照。

## 管理端交互

- 商品编辑抽屉桌面端最大宽度约 1100px，小屏幕自动占满可用宽度。
- “分公司限制”和“经销商限制”上下排列，各自占满编辑区域宽度。分公司区域提供搜索框、复选框和每个分公司的有效客户数量；经销商区域只显示当前选中分公司的名单。
- 多个已选分公司通过标签切换当前经销商列表。经销商支持当前分公司内关键词搜索，列表使用三列布局并独立滚动；窄屏自动切换为单列。
- 分公司和经销商范围变化不改变客户类型、图片、价格或商品基础信息。活动开始后修改下单范围必须填写修改原因，原因输入框全宽显示，保存前端和后端都强制校验。
- 下单范围编辑只在商品和白名单确认发布后开放经销商名单维护；导入预览阶段仍可维护 Excel 分公司范围。接口资源暂不可用时不提前请求经销商接口，也不阻断分公司预览。

## 操作与继承

商品和白名单确认导入后，在商品编辑中维护经销商名单。预览阶段可维护分公司，指定经销商配置在确认后进行。

同一活动重新导入商品，只有在完整 business_key（客户类型、返利类型、标准化名称、代码）匹配且新旧分公司范围标准化集合完全一致时，才继承指定名单。分公司集合为空统一表示“全部分公司”；新旧都为空可以继承，一方为空、一方有值或集合新增、删除、替换时均不继承，也不提示，直接使用本次 Excel 范围。

无法匹配的旧受限商品在确认导入前提示，新增商品采用 Excel 分公司范围；不跨活动继承。白名单换批次产生新的 activity_customer ID，但稳定身份不变时 customer ID 不变，名单继续生效。改名、换分公司、改类型、移除或停用会使原指定关系失效。限制标记独立保存，即使全部成员失效仍然保持限制，后台显示待处理。

历史订单不因修改权限被删除或改写。新提交、修改、重新提交、草稿保存和后台代客下单都校验当前身份和权限；原请求幂等重放只返回既有结果。活动开始后范围修改必须填写原因，保存修改前后范围、操作者、时间；商品版本号防止并发覆盖。待开始按现有规则需撤回发布，截止后只读。

## 数据和接口

V030 新增 activity_product_dealer_scope（分公司指定模式标记）、activity_product_dealer_member（稳定客户与身份快照）、product_scope_change_log（事务内日志）。保留既有 activity_product_branch_scope。

- GET /admin/activities/{activityId}/product-dealer-scopes：当前商品范围、指定名单有效状态、effectiveCount、selectedCount 和 restricted，只返回管理员。
- GET /admin/activities/{activityId}/product-dealer-candidates：当前有效客户的精简身份信息，不含手机号；编辑器本地搜索、每次展示 50 条并可加载更多。
- PATCH /admin/activities/{activityId}/products/{id}：dealerScope 为 [{branchName,customerIds}]，与商品和分公司修改同事务提交；省略表示保留，空数组表示显式清除指定名单。
- GET /admin/activities/{activityId}/products/{id}/scope-history：最近 100 条范围修改记录。

H5 不接收经销商授权名单，后端商品查询与订单校验共用权限 SQL。

## 验证与部署

运行 pnpm typecheck、pnpm lint、pnpm test、Maven test；前端范围选择器专项测试覆盖默认全选、取消全选、恢复全选、分公司切换、客户类型筛选和同名经销商。ProductDealerScopeIntegrationTest 需 ORDER_SHOW_SCOPE_TEST=1，固定连接专用 scope_test 数据库（host.docker.internal:18306），禁止指向业务库。测试会重建该测试库的夹具表。

部署需后端先执行 V030、V031，再更新前端。V031 会清理历史商品版本中因分公司范围变化而残留的指定名单。旧数据无经销商范围记录时，原分公司权限保持不变；业务环境已完成 V030、V031、backend 和 frontend 更新，MySQL、Redis、MinIO 数据服务及数据卷保持不变。
