# 商品自动计价（简化版）

管理员保存基础箱价、阶梯门槛、优惠价、计价模式或取消优惠后，同事务直接更新当前活动、同商品 ID 的 SUBMITTED 订单。整批和分段计价都以每张订单中该商品箱数计算。

只更新 order_item 的价格字段、customer_order 的总金额、内部锁版本和更新时间。不新增 order_version、order_operation、price_sync_batch 或独立调价审计。原有商品保存审计按既有机制保留；旧订单版本不删除。数量、吨数、其他商品快照及首次提交时间保持原值。

前端仅提示保存成功；没有调价预览弹窗、同步复选框或同步按钮。当前订单详情、管理员改单初始值来自当前明细，不从旧版本读取。历史版本可单独查看，但不代表最新成交金额。

商品及相关订单在同一事务内提交，订单写入与商品调价先锁活动行，订单写事务使用 READ_COMMITTED 保证等待后读取最新价格。普通商品资料修改不触发同步。无有效价格但已存在有效订单的修改会被拒绝并整体回滚。

看板由 outbox 失效通知刷新；已结束的展示快照沿用后端刷新机制。H5 查看页根据内部锁版本检查更新，只更新最新金额，不展示调价或版本提示。客户未提交的编辑数量不被后台自动覆盖。

部署补处理：先备份，使用 PRICE_SYNC_BACKFILL_ACTIVITY_ID 指定一个进行中的活动，启动后按当前目录逐商品校正有效订单，成功后移除配置。默认不执行，重复执行无价格变化时不写订单。此前的手动 price-sync API 和弹窗已移除，已应用的 V024 表保留。

## 实现边界

- `PriceSyncService` 负责价格变化判断、同步顺序、回填校验和事务入口，不直接执行 SQL。
- `PriceSyncRepository` 读取当前目录与有效订单明细、更新当前价格和订单总额；使用明确的 `CurrentItem`、`CatalogPrice` 类型。
- `OrderRepository` 提供活动价格锁和 outbox 写入，价格同步不再通过 `OrderService` 转发。
- `OrderPricingCalculator` 提供共用计价与数值比较；数值比较忽略小数位差异并保留原有空值规则，订单服务不再反向依赖价格同步服务。

同步顺序保持为：锁活动、查询有效明细、判断价格变化、更新明细、更新订单总额、写事件，最后按原规则刷新展示快照。回填仍在原事务中逐商品同步，不引入新事务、并发处理或额外订单版本。

自动价格同步与管理员主动调整仍是两条不同业务路径：前者不新增历史版本；后者继续由订单服务及 `OrderRepository.saveRepriced` 按原规则维护版本。不能因为二者共用计价函数而合并持久化语义。
