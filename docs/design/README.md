# 订购会系统详细设计交付索引

> 实施状态（2026-08-24）：本设计基线已在当前仓库完成首版实现；运行方式、已导入数据和验收命令见根目录 `README.md`。

## 1. 文档定位

本目录是订购会系统正式开发的设计基线。业务依据按优先级依次为：

1. 用户已经明确确认的决策；
2. `PROJECT.md` 中的最新规则；
3. 《订购会 PRD》；
4. 当前已确认并接入正式接口的 React UI。

发生冲突时采用优先级更高的规则。当前采用的订单业务状态为“已提交、已撤回”；活动截止通过活动状态和截止时间控制只读，不额外把全部订单改写为“已锁定”。

### 2.1 当前实现边界

| 能力 | 当前状态 |
| --- | --- |
| 前端 | 一个 React + TypeScript + Vinext/Vite 工程，复用现有自定义 UI，按视图提供 H5、后台、排行、战报和抽奖 |
| 后端 | 一个 Java 21 + Spring Boot 模块化单体进程 |
| 持久化 | MySQL 保存业务事实，Redis 提供抽奖互斥等辅助能力，MinIO 保存导入文件和商品图片 |
| 本地运行 | Docker Compose 同时启动前端、后端、MySQL、Redis 和 MinIO |
| 后台任务 | 导入任务状态保存在 MySQL，当前由 Spring Boot 应用内执行器处理；尚未拆分独立 Worker |
| 数据库迁移 | 本地后端启动时执行 Flyway；独立 Migration Job 是生产部署目标 |
| 实时数据 | 后台概览每 10 秒读取真实统计；排行/战报支持 SSE 失效通知后重新查询 |
| 管理员电话 | 白名单和到场管理页显示完整电话；订单、H5、大屏和日志保持脱敏 |

## 3. 已确认业务基线

- 系统支持多场活动，活动可有不同场次和时间，历史数据全部保留。
- 商品、白名单、到场名单、订单、看板、导入、抽奖及审计数据均关联活动 ID。
- 一期只有“管理员”角色，但支持多个独立管理员账号，禁止共享账号。
- H5 仅使用手机号匹配白名单，不使用短信验证码。
- 同一手机号允许分别存在于综合和特渠通道；同一活动、同一客户类型内手机号重复在导入阶段阻断确认。
- H5 凭证最晚在活动结束时失效；关闭浏览器会话后再次进入重新输入手机号。
- 同一活动、同一客户只有一个订单号；首次提交为 V1，之后成功重提形成新版本。
- 订单只有“已提交、已撤回”两个业务状态；活动截止后统一只读。
- 订单提交、修改、撤回和重新提交只能由客户在 H5 操作；管理后台只能查看、搜索、筛选和导出订单，不能改变订单内容或业务状态。
- 已撤回订单保留最近一次非空明细和版本，但不参与看板和抽奖。
- 金额和吨数由后端根据商品快照重新计算。
- 抽奖主体为活动客户代表的经销商，内部按活动客户 ID 去重，名称仅用于展示。
- 商品、白名单和现场到场 Excel 都按完整版本全量替换，当前业务只读取最近发布版本。
- “现场到场客户”每次发布按客户类型内手机号、全称、同分公司简称重新精确关联；白名单重新发布也会重算。只有状态为“已关联”且指向当前有效 `activity_customer` 的记录进入候选池。
- 目标规模为单场几百个商品、约千人同时在线；上线前按 2 倍目标压力测试。
- 第一阶段允许完全在本地开发，正式部署平台暂不绑定具体厂商。

## 4. 设计默认值

以下未被业务明确指定的内容使用安全且可变更的默认值：

- 时区：活动默认 `Asia/Shanghai`；数据库时间保存 UTC 时间点。
- 金额：价格保存 4 位小数，明细和订单金额按 HALF_UP 保留 2 位。
- 商品展示与可订：已启用且物料名称有效的商品进入 H5；只有有效元/箱决定是否可加入购物车，缺少其他可选字段时隐藏对应信息。
- 吨数：转换系数可空；有值时保存 8 位小数、计算结果保存 6 位并默认展示 4 位。任一订单明细无法换算时，订单总吨数整体为空。
- 跨轮次中奖：默认排除本活动已中奖经销商，可在轮次规则中显式允许重复。
- 商品数量：非负整数；单项默认最大 999999 箱，后端配置可调整。
- 看板：订单提交后 3 秒内通过 SSE 推送失效事件，客户端重新读取统计快照。
- 管理员登录：账号密码 + HttpOnly 安全会话 Cookie；首次登录强制修改密码。
- 数据删除：业务 UI 只提供当前版本删除，不提供停用/恢复；底层可保留不可见历史记录，订单版本、抽奖结果和审计日志不可物理删除。

## 5. 上线前可按现场口径微调的展示项

以下内容均已有可运行默认值，不阻塞开发和本地验收；如业务现场需要，可在上线演练前微调：

- 九类专题战报每一列的最终名称、排序和并列排名展示方式；
- 订单汇总、明细、历史版本和中奖名单的最终 Excel 列顺序；
- 吨数页面最终展示 3 位还是 4 位；数据库精度不受影响；
- 管理员是否允许在活动开始后修改单条商品和白名单；设计默认允许但必须填写原因并审计。

## 6. 使用方式

1. 当前运行、导入数据和验收命令先查看根目录 `README.md`。
2. 修改后端字段时同时更新 OpenAPI、`app/api.ts` 类型和对应数据库迁移，禁止前后端各自猜测字段。
3. 修改状态或权限时同步更新状态机、权限矩阵和自动测试。
4. 上线审查使用权限矩阵、审计清单、备份与压测要求逐项验收。
