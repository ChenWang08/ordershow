本目录是订购会系统正式开发的设计基线。业务依据按优先级依次为：

1. 用户已经明确确认的决策；
2. `PROJECT.md` 中的最新规则；
3. 《订购会 PRD》；
4. 当前已确认并接入正式接口的 React UI。

发生冲突时采用优先级更高的规则。当前采用的订单业务状态为“已提交、已撤回、已作废”；活动截止通过活动状态和截止时间控制客户侧只读，不额外把全部订单改写为“已锁定”。

## 3. 已确认业务基线

- 系统支持多场活动，活动可有不同场次和时间，历史数据默认长期保留；超级管理员可手动归档，或明确永久删除整场活动并保留独立删除凭证。
- 商品、白名单、到场名单、订单、看板、导入、抽奖及审计数据均关联活动 ID。
- 商品 Excel 使用一个非空 Sheet，Sheet 名称不限；客户类型和是否返利可为空。判重先按客户类型、返利类型和标准化物料名称分组；两行代码都有值时，代码相同才重复，任一代码为空时同名即重复。物料代码参与判重但不参与图片匹配；图片仍按完整标准化物料名称匹配，同名商品共享图片。产品说明保存到商品目录并由 H5 详情展示。
- H5 商品目录只有在同时存在参与和不参与返利商品时才显示两个返利页签，否则显示“全部商品”；返利为空的商品按通用商品处理。商品说明过长时在卡片说明区域内部滚动，价格和数量控件保持可用；后台待确认图片列显示候选图片数量数字。
- 白名单和商品客户类型全部为空时，活动概览保留“全部客户/综合客户/特渠专业客户”三行进度且综合、特渠为 0；订单看板按全量客户汇总，订单额占比位置显示“全部客户 100%”环形图并隐藏渠道和片区模块；排行按全部客户口径展示，专题战报保留入口和页面但显示“暂不展示”占位。
- 白名单 Excel 使用一个非空 Sheet，Sheet 名称不限；第一列为客户类型，可全量填写综合/特渠或全量留空，`经销商类型` 不再是模板必填字段。判重为有类型时“客户类型 + 经销商全称 + 所属分公司”，无类型时“经销商全称 + 所属分公司”；手机号按客户类型唯一，综合/特渠可以复用手机号。
- 当前实现为“超级管理员 + 每部门一个部门管理员 + 多个独立成员”；六项权限覆盖本部门全部活动，成员不可创建、配置、发布或结束活动。成员验收入口见 `../../tests/README.md`，一期历史与其他待验收事项见 `07-department-account-and-activity-isolation-plan.md`。
- H5 仅使用手机号匹配白名单，不使用短信验证码；白名单客户类型全部为空时直接输入手机号进入订货，有类型时保持通道选择。
- 综合客户大区由当前生效白名单动态产生；白名单大区为自由文本且选填，空值走“不分大区”路径，全部未分大区时跳过大区选择；特渠不使用综合大区。
- 同一手机号允许分别存在于综合和特渠通道；同一活动、同一客户类型内手机号重复在导入阶段阻断确认，空客户类型按不区分类型的 `ALL` 范围判重。
- H5 凭证最晚在活动结束时失效；关闭浏览器会话后再次进入重新输入手机号。
- 同一活动、同一客户只有一个订单号；首次提交为 V1，之后成功重提形成新版本。
- 订单有“已提交、已撤回、已作废”三个业务状态；活动截止后客户只读，管理员仍可按部门权限维护。
- 客户在 H5 只能在活动截止前首次提交、增加订货、恢复失效订单或创建减量/撤回申请；首次提交、仅增加数量或新增商品直接生效；有效订单减少任一商品数量、删除商品或整单撤回时，整次变更需审核，审核前原订单不变。已撤回或已作废订单在订货截止前重新提交时直接恢复，不与失效前数量比较，沿用原订单号并保留历史。商品和数量完全未变时不更新订单或创建申请。活动开始后，超级管理员、本部门管理员及拥有 ORDER 权限的本部门成员还可新增、调整、恢复或逻辑作废订单，操作必须记录来源、原因、版本和审计。
- 已撤回订单保留最近一次非空明细和版本，但不参与看板和抽奖；商品自动计价只处理 `SUBMITTED` 订单，不恢复撤回或作废订单。
- 提交时金额和吨数由后端计算；商品价格保存后，当前有效订单的价格和金额按最新商品规则自动重算，吨数不因价格变化重算。
- 抽奖主体为活动客户代表的经销商，内部按活动客户 ID 去重，名称仅用于展示。
- 商品、白名单和现场到场 Excel 都按完整版本全量替换，当前业务只读取最近发布版本。
- “现场到场客户”每次发布按参会人员类型限定客户通道，再优先使用“客户类型 + 分公司 + 经销商全称”，其次使用“客户类型 + 分公司 + 经销商简称”重新精确关联；白名单重新发布也会重算。现场手机号只作联系信息，不参与新关联。只有状态为“已关联”且指向当前有效 `activity_customer` 的记录进入候选池。
- 目标规模为单场几百个商品、约千人同时在线；上线前按 2 倍目标压力测试。
- 第一阶段允许完全在本地开发，正式部署平台暂不绑定具体厂商。

## 4. 设计默认值

以下未被业务明确指定的内容使用安全且可变更的默认值：

- 时区：活动默认 `Asia/Shanghai`；数据库时间保存 UTC 时间点。
- 金额：价格保存 4 位小数，明细和订单金额按 HALF_UP 保留 2 位。
- 商品展示与可订：已启用且物料名称有效的商品进入 H5；只有有效元/箱决定是否可加入购物车，缺少其他可选字段时隐藏对应信息。
- 吨数：转换系数可空；有值时保存 8 位小数、计算结果保存 6 位并默认展示 4 位。任一订单明细无法换算时，订单总吨数整体为空。
- 跨轮次中奖：第一轮不排除已中奖客户；第二轮起可在轮次规则中按白名单客户 ID 排除当前有效中奖客户。
- 商品数量：非负整数；单项默认最大 999999 箱，后端配置可调整。
- 看板：活动进行中或仅订货截止时，订单变化在 3 秒内通过 SSE 推送失效事件，客户端重新读取统计快照；整场活动结束后停止实时推送，管理员订单维护仍会自动更新最终展示快照。
- 后台登录：账号密码 + HttpOnly 会话 Cookie；仅超级管理员首次登录强制改密。部门管理员和成员的密码由上级管理员管理，均不能自行修改。
- 数据删除：普通业务 UI 只提供当前版本删除，不提供停用/恢复，底层可保留不可见历史记录。超级管理员可永久删除草稿、已结束、已归档整场活动，订单版本、抽奖结果、活动审计及文件随任务清理；无自动备份、无回收站，独立删除凭证保留。归档及解除归档只改变活动管理状态，不清理业务数据。

以下内容均已有可运行默认值，不阻塞开发和本地验收；如业务现场需要，可在上线演练前微调：

## 6. 使用方式

1. 当前运行、导入数据和验收命令先查看根目录 `README.md`。
2. 修改后端字段时同时更新 OpenAPI、`app/api.ts` 类型和对应数据库迁移，禁止前后端各自猜测字段。
3. 修改状态或权限时同步更新状态机、权限矩阵和自动测试。
