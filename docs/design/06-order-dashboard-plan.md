# 订单综合看板方案

> 当前实现状态（2026-09-04）：综合/特渠模式和“不区分客户类型”模式的订单看板、活动概览提交进度、全部客户排行和战报界面适配已完成前端接线；真实浏览器视觉验收仍需在可用浏览器或真机环境中执行。

## 1. 页面定位

订单综合看板用于现场总览，回答“订了多少、由谁贡献、集中在哪些区域和项目组、当前下单节奏如何”。它与另外两块大屏分工如下：

- 订单看板：全场订单规模、渠道结构、区域贡献、项目组贡献、小时趋势和金额排行。
- 订货排行：经销商与分公司的有效订单金额或可计算吨数名次。
- 专题战报：礼盒、渠道、区域和项目组等指定主题的集中展示。

页面地址为 `/screen/{activityCode}/dashboard`。当前页面使用浅灰背景、白色数据卡、紫色渐变标题栏和多色图表体系，所有模块标题使用加粗样式。

## 2. 全局统计口径

- 所有指标只统计当前活动、当前订单版本且状态为 `SUBMITTED` 的订单。
- `WITHDRAWN` 订单不参与统计；重新提交后重新进入统计。
- 待审核的客户变更申请不改变当前订单和统计口径；审核通过后以新当前版本替换旧版本，不重复累计历史版本。
- 金额使用当前有效订单的 `customer_order.total_amount` 和 `order_item.line_amount`；商品基础价或阶梯规则保存后，相关 `SUBMITTED` 订单自动按最新规则更新当前金额。历史 `order_version_item` 保留提交时价格，不参与当前统计。
- 公开看板不展示手机号、确认人电话等敏感字段。
- 订单看板中的项目组模块只展示订单额；订货排行按当前选择的金额或吨数展示，均不展示订货箱数。
- 活动整场结束并进入 `FINISHED` 后停止实时推送并读取最终展示快照；管理员新增、调整或作废订单后由服务端自动刷新该快照，展示数据仍按最新有效订单变化，不需要手工重新生成。超级管理员可手动归档到 `ARCHIVED`，此后冻结全部业务写入并保留历史快照读取；解除归档恢复已结束。

## 3. 模块与指标定义

### 3.1 顶部状态栏

| 内容 | 数据来源 | 展示规则 |
| --- | --- | --- |
| 页面标题 | 固定文案 | 订货会订单数据可视化看板 |
| 活动名称 | 活动配置 | 显示当前路由对应活动名称 |
| 看板状态 | 最近读取的活动状态 | 进行中显示“手动更新”，历史活动显示“历史回看” |
| 手动刷新 | 看板接口 | 点击后重新获取整张看板快照，刷新期间按钮不可重复点击 |
| 最近刷新时间 | 最近一次成功读取完成时间 | 按北京时间显示；失败保留旧时间，历史数据仍明确标记“历史回看” |

### 3.2 六项核心指标

| 指标 | 计算口径 | 展示规则 |
| --- | --- | --- |
| 订单总额 | 有效订单 `total_amount` 求和 | 元；大数缩写为万/亿 |
| 订单总吨数 | 有效订单明细中非空 `line_tons` 求和 | 无可折算明细时显示“待完善” |
| 订单总笔数 | 有效订单数量 | 单位为笔 |
| 参与经销商 | 有效订单对应经销商数量 | 当前单客户单订单模型下通常与订单总笔数一致，独立保留指标便于后续扩展 |
| 参与分公司 | 有效订单分公司快照去重 | 单位为家 |
| 成交 SKU | 有效订单明细 `activity_product_id` 去重 | 只统计实际成交商品，单位为种 |

### 3.3 渠道订单额占比

- 按 `customer_type` 汇总综合客户与特渠专业客户的有效订单金额。
- 分母为全渠道订单总额。
- 使用双色环形图展示，图例同时显示两个渠道的订单额。
- 不展示箱数。
- 只有当前活动同时存在综合和特渠两类有效白名单客户时，才显示“渠道订单额占比”。客户类型全部为空时显示“全部客户”订单额摘要；只有一种客户类型时显示对应的单类型订单额摘要，不制造空渠道对比。

### 3.4 综合客户片区订单额分布

- 只统计综合客户，按当前生效白名单实际使用的 `region_code` 汇总有效订单金额和订单笔数。
- 只有当前活动存在综合客户类型时展示；只有特渠或客户类型全部为空时隐藏该模块。
- 当前白名单中已填写但没有订单的片区补 0；大区为空的综合订单不进入具体片区卡片。
- 每个片区使用独立颜色，横向进度条显示相对金额，右侧显示订单额。
- 片区名称旁可以显示订单笔数，但不显示箱数。

### 3.5 项目组订单额排名（全渠道）

- 汇总综合客户和特渠专业客户的有效订单明细。
- 按商品快照 `product_line` 聚合订单额并降序排列。
- 当前大屏展示前 6 条项目组，只有订单额，不展示箱数。
- 每条项目组使用独立颜色，同一项目组在后续模块中保持相同颜色。

### 3.6 下单时间趋势（按小时）

- 使用当前有效订单的 `last_submitted_at` 按小时汇总订单额和订单笔数。
- 修改后的订单归入最后一次提交所在小时，不累计旧版本。
- 查询范围从 `actualStartedAt` 开始；没有实际开始时间时使用 `startsAt`。
- 活动进行中以接口 `dashboard.generatedAt` 作为当前时间；活动截止后使用 `closedAt`，没有实际截止时间时使用 `endsAt`。
- 接口时间桶使用带 `Z` 的 UTC 标准时间，页面统一按照活动配置的时区显示。
- 从活动开始所在小时到当前/截止所在小时连续生成时间点，没有订单的小时补 `0 元 / 0 笔`。
- 零值点准确落在纵轴零线，不因横轴文字改变绘图区高度。
- 曲线使用绿色平滑线、浅绿色面积填充和绿色小圆点。
- 图表默认滚动到最新小时，可按住鼠标或触摸横向拖动，也可使用底部横向滚动条。
- 每个点都可以点击；详情显示活动时区下的完整时间、订单金额和订单笔数，零值点同样可查看。
- 标题右侧显示总小时数和零值小时数。
- 当当前活动不是双渠道对比模式（客户类型全部为空或只有一种类型）时，趋势图横跨看板整行；双渠道活动保持原双栏布局。
- 单一客户类型或全部客户模式下，“订单额占比”和“项目组订单额排名”并排显示；如果存在综合客户大区订单额分布，则该模块放在下一行，时间趋势继续放在其后并横跨整行。

### 3.7 各渠道项目组订单额对比

- 分为“特渠专业客户”和“综合客户”两栏。
- 分别按商品快照 `product_line` 汇总有效订单明细金额。
- 只显示订单额，不展示箱数。
- 项目组颜色与全渠道项目组排名保持一致。
- 只有综合和特渠两类客户同时存在时展示；客户类型全部为空或只有一种类型时隐藏，避免空渠道或无比较意义的图表。

### 3.8 综合渠道各片区项目组订单额明细

- 只统计综合客户，按 `region_code + product_line` 汇总有效订单明细金额。
- 只有当前活动存在综合客户类型时展示；只有特渠或客户类型全部为空时隐藏。
- 片区卡片顺序跟随当前白名单大区顺序（历史大区使用内部名称字典兜底）；片区标题使用独立片区色，并显示片区订单总额。
- 每个片区内的项目组顺序跟随综合渠道全局项目组排名。
- 缺失的“片区 + 项目组”组合补 0。
- 只显示订单额，不展示箱数；项目组颜色与其他项目组模块保持一致。

### 3.9 分公司订单额/吨数排名 TOP 15

- 本节与 3.10 的 TOP 15 指订单综合看板中的两个排行卡片；独立订货排行页面的公司 90/分公司 30 规则见 3.11。
- 订货排行页面支持在“金额排行”和“吨数排行”之间切换；默认按订单金额展示。
- 金额模式按订单中的分公司快照汇总有效订单金额并降序排列；吨数模式按当前有效订单明细中非空 `line_tons` 汇总并降序排列。
- 展示名次、分公司名称和当前口径的数值；金额模式显示订单额，吨数模式显示吨数，不展示箱数。
- 颜色条高度为 6px，并使用圆角样式提高大屏可读性。
- 排名卡片内部纵向滚动，页面截取并展示前 15 名。

### 3.10 经销商订单额/吨数排名 TOP 15

- 金额模式按当前有效订单金额降序排列经销商；吨数模式按当前有效订单明细中非空 `line_tons` 汇总并降序排列。
- 展示名次、经销商名称、所属分公司和当前口径的数值；金额模式显示订单额，吨数模式显示吨数，不展示箱数。
- 颜色条高度为 6px，并使用圆角样式提高大屏可读性。
- 排名卡片内部纵向滚动，页面截取并展示前 15 名。

### 3.11 排行口径与吨数缺失规则

- 独立订货排行页面 `/screen/{activityCode}/ranking` 新建活动默认公司前 **90** 名、分公司前 **30** 名；不足上限时全部展示，超过上限时按当前口径取前 N 名。金额/吨数、全部客户/特渠/综合各大区均先按当前范围筛选，再分别排名。页面将接口返回的公司列表分成三列，不另行截取 20 名。已明确自定义的活动上限继续保留。
- 窄窗口不隐藏第 2、3 列客户和分公司榜：640px 以下公司三列依序纵向排列，1000px 以下分公司榜放在客户排行之后，可以滚动查看。大屏三列加分公司侧榜布局保持不变。
- 后台“已提交客户”和顶部金额、箱数、吨数统计基于全量有效 `SUBMITTED` 订单，不受排行展示上限影响。订单综合看板 `/dashboard` 的两个 TOP 15 卡片仍各展示前 15 名，与独立订货排行页面的 90/30 规则分开。
- 金额/吨数切换同时作用于公司和分公司两个排行模块，客户类型和大区筛选保持不变。
- 排行接口的 `metric` 参数支持 `AMOUNT` 和 `TONS`，不传时默认为 `AMOUNT`；金额历史快照继续使用原有快照键，吨数历史快照使用独立快照键。
- 吨数排行沿用看板口径：部分商品可换算时汇总非空 `line_tons`；订单明细全部无法换算的公司或分公司不进入吨数榜。整个筛选范围没有可计算吨数时显示“暂无可计算吨数”。
- V036 曾将缺失吨数保存为 `0`。吨数榜不能只用 `COALESCE(SUM(line_tons), 0)` 判断可计算性：换算系数存在的已保存吨数（包含精度舍入为 0 的结果）及历史已保存的正吨数参与汇总；系数缺失且吨数为 NULL/0 的占位值不作为可计算吨数。只读取订单明细快照，不读当前商品系数、不修改订单金额或吨数。
- 吨数保留 3 位小数；同口径数值相同时按金额、提交时间和名称等稳定字段排序。
- 新增排行口径不改变订单吨数计算、金额计算或数据库结构。
- 旧页面创建活动时误传公司/分公司 `20/20`，覆盖了数据库的 `90/30` 默认值。修复新建默认值不会自动修正已有活动；核对后按指定活动名单修正，已结束活动需同时失效并重建相关展示快照。自定义配置和 `ARCHIVED` 冻结数据不批量覆盖，操作步骤见 [排行部署与旧活动修正](../deployment/2026-10-27-ranking-limits.md)。

### 3.12 不区分客户类型模式（已实现）

本节适用于当前活动白名单客户类型全部为空、商品客户类型也全部为空的场景。系统内部使用 `ALL` 表示该模式，当前 H5 可直接输入手机号进入订货。该模式的看板、活动概览和后台相关展示按以下规则实现：

- 活动概览保留“全部客户、综合客户、特渠专业客户”三行提交进度；全部客户使用全量白名单和提交数据，综合客户与特渠专业客户在不区分模式下均显示为 0。
- 订单综合看板按全量有效订单汇总；原渠道占比位置改为“订单额占比”环形图，显示“全部客户”100%和全量订单金额，零订单时显示 0% 灰色空环。渠道对比和所有片区相关模块隐藏；全渠道项目组、分公司、经销商和小时趋势继续按当前有效订单统计。
- 排行和专题战报的入口、路由和页面保留；不区分模式下排行使用“全部客户”口径读取 `ALL` 订单并正常展示，专题战报仍显示“暂不展示”占位，避免产生无分类依据的类型战报。
- 后台订单、现场到场和抽奖相关筛选及标签不得把 `ALL` 显示成综合或特渠；现场到场显示“全部客户/不区分客户类型”，抽奖规则在该模式使用“全部客户”；有类型活动继续保持现有通道规则。
- 该模式优先由当前白名单发布版本的客户类型模式驱动；接口继续使用 `ALL` 及现有订单聚合字段，不通过前端伪造客户类型，也不新增数据库类型值。

## 4. 颜色与布局规范

- 所有白色数据卡标题使用粗体，并在标题前显示对应主题色圆点。
- 项目组使用 20 色调色板；前 20 条项目组使用不同颜色，超过 20 条后循环使用调色板。
- 项目组颜色映射以全渠道项目组排名为主，同一项目组跨“全渠道排名、渠道对比、片区明细”保持一致。
- 当前白名单实际大区使用独立片区色，与项目组色分别管理。
- 金额条以当前模块最大金额为 100% 计算相对长度；金额为 0 时不绘制彩色长度。
- 分公司和经销商排行的金额颜色条为 6px，其他普通金额条按对应模块样式展示。
- 趋势图的纵轴固定在左侧，横轴在独立区域展示，长时间范围通过横向滚动承载。
- 宽屏使用双列及多列卡片布局；窄屏自动切换为单列，页面本身不产生非预期横向溢出。

## 5. 数据接口与字段映射

聚合接口：`GET /screen/activities/{activityCode}/dashboard`。

| 响应字段 | 页面用途 |
| --- | --- |
| `dashboard.totals.total_amount` | 订单总额 |
| `dashboard.totals.total_tons` | 订单总吨数 |
| `dashboard.totals.order_count` | 订单总笔数 |
| `dashboard.totals.dealer_count` | 参与经销商 |
| `dashboard.totals.branch_count` | 参与分公司 |
| `dashboard.totals.sku_count` | 成交 SKU |
| `dashboard.productLines` | 全渠道项目组订单额排名 |
| `dashboard.branches` | 分公司订单额 TOP 15 |
| `dashboard.companies` | 经销商订单额 TOP 15 |
| `dashboard.generatedAt` | 快照更新时间和进行中趋势终点 |
| `customerTypes` | 综合/特渠订单额及渠道占比 |
| `generalRegions` | 自描述的综合客户片区数组；包含片区编码、名称、顺序、订单笔数、金额及项目组明细 |
| `regions` | 兼容字段：综合客户片区订单额与订单笔数 |
| `generalProductLines` | 综合客户项目组订单额 |
| `specialProductLines` | 特渠专业客户项目组订单额 |
| `regionProductLines` | 综合客户各片区项目组订单额明细 |
| `trend` | UTC小时桶、小时订单额和订单笔数 |

接口仍可能携带其他兼容字段，但订单看板只使用上表字段。所有金额在前端转换为数值后格式化，公开响应不得包含完整手机号。

片区维度由当前生效综合客户白名单和实际订单共同驱动，不写死东区、南区或北区。白名单中的非空大区按稳定编码和白名单顺序返回，暂无订单的片区及“片区 + 项目组”组合补 0；遇到历史或异常的未配置片区时使用内部名称字典兜底并追加展示。空大区订单不归入具体片区；当当前白名单没有任何非空大区时，`generalRegions` 返回空数组，前端隐藏片区分布和片区项目组明细。片区卡片桌面端每行最多 4 张并自动换行，各卡片共用同一金额刻度，保证横向比较有效。

## 6. 刷新、状态与异常处理

- 首次进入订单看板、订货排行或专题战报时，等活动信息就绪后加载一次。切换活动时取消旧请求并首次加载新活动。
- 三个页面均只在首次加载或点击“手动刷新”时读取统计；不建立统计 SSE 订阅、不轮询，也不在网络重连、订单变化或活动资料变化时自动读取统计。抽奖及服务端事件发布规则沿用原行为。
- 查询期间禁用刷新按钮，相同页面的重复点击共用正在执行的请求，不再追加一次尾随查询。
- 显示最近成功读取的北京时间；刷新失败保留旧数据和旧时间，提示当前显示上次成功加载的数据并支持点击重试。
- 排行的金额/吨数和客户/大区筛选先暂存，点击刷新成功后才与数据一起应用；待应用或刷新失败期间，原榜单标题、单位和数值保持对应。
- 专题战报首次读取包含所有展示类型的数据，切换战报仅切换展示；点击刷新才重新获取。未区分客户类型的活动继续显示“暂不展示”且不请求战报。
- 当前小时订单新增、修改、撤回、重新提交或商品调价后，点击刷新才更新金额、排行和趋势。跨整点后的小时点也在下次成功读取时更新。
- `FINISHED` 显示“历史回看”并读取最终 `REPORT` 快照；管理员订单维护成功后服务端刷新该快照，点击手动刷新可读取更新后的快照。`ARCHIVED` 读取归档时冻结的快照。永久删除受理后，相关看板、排行、战报和文件访问立即失效。

## 7. 页面顺序

1. 紫色渐变标题栏。
2. 六项核心指标卡片。
3. 渠道订单额占比、综合客户片区订单额分布（不区分客户类型模式下改为“订单额占比”全部客户环形图，并隐藏片区分布）。
4. 双渠道模式下展示项目组订单额排名（全渠道）和下单时间趋势（按小时）；单一客户类型或全部客户模式下，订单额摘要与项目组订单额排名并排，趋势图单独占满下一行。
5. 各渠道项目组订单额对比（不区分客户类型模式隐藏）。
6. 综合渠道各片区项目组订单额明细（不区分客户类型模式隐藏）。
7. 分公司订单额排名 TOP 15、经销商订单额排名 TOP 15。

当前页面不再展示“各渠道项目组订货箱数”“订货总箱数”“最新有效订单”等旧模块。

## 8. 验收标准

- 首次加载后静置一分钟、订单变化或网络重连均不追加统计查询；点击刷新后数据正确变化。
- 连点刷新不产生并行或尾随查询，筛选变更不自动查询，失败不清空已加载数据或更新时间。
- 六个核心指标能与订单导出按同一有效订单范围复核。
- 渠道、片区、项目组及排行小计不存在重复累计。
- 项目组订单额排名、渠道项目组对比、片区项目组明细、分公司排名和经销商排名均不显示箱数。
- 同一项目组在各模块中颜色一致，至少支持 20 种项目组配色。
- 所有模块标题为粗体；底部排行颜色条为 6px 且清晰可见。
- 分公司和经销商排名均最多展示15名，内容超出卡片时可以纵向滚动。
- 趋势第一小时不早于活动实际开始所在小时，活动开始前的订单数据不进入统计。
- UTC时间桶按活动时区正确显示，例如 `08:00Z` 在 `Asia/Shanghai` 显示为 `16:00`。
- 趋势连续补齐到当前/截止小时；无订单小时为 `0 元 / 0 笔`，点位落在零轴。
- 趋势图可以横向拖动，每个数据点均可点击查看完整时间、订单金额和订单笔数。
- 看板接口和 DOM 不出现手机号、确认人电话等敏感字段；管理员订单接口按权限返回完整电话，不复用到看板。
- 宽屏投放可正常阅读，窄屏自动改为单列，不出现非预期横向溢出。
- 活动结束后页面显示“历史回看”；管理员订单维护后，刷新页面会显示更新后的最新结果，不需要运营人员手工重新生成报表。
- 白名单和商品客户类型全部为空时，活动概览显示“全部客户、综合客户、特渠专业客户”三行提交进度，其中综合客户和特渠专业客户为 0；看板所有金额、订单数、项目组、分公司和经销商统计与订单导出全量口径一致。
- 不区分客户类型模式不显示渠道拆分和片区相关模块；排行以“全部客户”口径正常展示，专题战报入口与页面保留但显示“暂不展示”占位；订单管理、到场和抽奖页面不把 `ALL` 错标为综合或特渠。
- 上述前端规则已完成代码和自动化接线检查，真实浏览器视觉验收仍需在可用浏览器或真机环境中执行。
