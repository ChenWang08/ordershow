# 订单综合看板方案

> 当前实现状态（2026-09-04）：综合/特渠模式的订单看板已实现；“不区分客户类型”模式下的看板、活动概览提交进度、排行和战报界面适配尚未实施。本文件第 3.11 节记录已确认的后续规则，不代表当前代码已经完成该适配。

## 1. 页面定位

订单综合看板用于现场总览，回答“订了多少、由谁贡献、集中在哪些区域和产品线、当前下单节奏如何”。它与另外两块大屏分工如下：

- 订单看板：全场订单规模、渠道结构、区域贡献、产品线贡献、小时趋势和金额排行。
- 订货排行：经销商与分公司的有效订单金额名次。
- 专题战报：礼盒、渠道、区域和产品线等指定主题的集中展示。

页面地址为 `/screen/{activityCode}/dashboard`。当前页面使用浅灰背景、白色数据卡、紫色渐变标题栏和多色图表体系，所有模块标题使用加粗样式。

## 2. 全局统计口径

- 所有指标只统计当前活动、当前订单版本且状态为 `SUBMITTED` 的订单。
- `WITHDRAWN` 订单不参与统计；重新提交后重新进入统计。
- 客户修改订单后以当前版本替换旧版本，不重复累计历史版本。
- 金额使用订单及订单明细提交时保存的业务快照；后续修改商品主数据不会回写历史订单。
- 公开看板不展示手机号、确认人电话等敏感字段。
- 订单看板中的产线和排行模块只展示订单额，不展示订货箱数。
- 活动整场结束并进入 `FINISHED` 或 `ARCHIVED` 后读取最终快照，不再随业务数据变化。

## 3. 模块与指标定义

### 3.1 顶部状态栏

| 内容 | 数据来源 | 展示规则 |
| --- | --- | --- |
| 页面标题 | 固定文案 | 订货会订单数据可视化看板 |
| 活动名称 | 活动配置 | 显示当前路由对应活动名称 |
| 看板状态 | 活动状态 | 进行中显示 `LIVE`，历史活动显示“历史回看” |
| 手动刷新 | 看板接口 | 点击后重新获取整张看板快照，刷新期间按钮不可重复点击 |
| 更新时间 | `dashboard.generatedAt` | 显示本次接口快照生成时间 |

### 3.2 六项核心指标

| 指标 | 计算口径 | 展示规则 |
| --- | --- | --- |
| 订单总额 | 有效订单 `total_amount` 求和 | 元；大数缩写为万/亿 |
| 订单总吨数 | 有效订单明细中非空 `line_tons` 求和 | 无可折算明细时显示“待完善” |
| 订单总笔数 | 有效订单数量 | 单位为笔 |
| 参与经销商 | 有效订单对应经销商数量 | 当前单客户单订单模型下通常与订单总笔数一致，独立保留指标便于后续扩展 |
| 参与分公司 | 有效订单分公司快照去重 | 单位为家 |
| 成交 SKU | 有效订单明细 `activity_product_id` 去重 | 只统计实际成交商品，单位为种 |

### 3.3 渠道订单额占比

- 按 `customer_type` 汇总综合客户与特渠专业客户的有效订单金额。
- 分母为全渠道订单总额。
- 使用双色环形图展示，图例同时显示两个渠道的订单额。
- 不展示箱数。

### 3.4 综合客户片区订单额分布

- 只统计综合客户，按当前生效白名单实际使用的 `region_code` 汇总有效订单金额和订单笔数。
- 当前白名单中已填写但没有订单的片区补 0；大区为空的综合订单不进入具体片区卡片。
- 每个片区使用独立颜色，横向进度条显示相对金额，右侧显示订单额。
- 片区名称旁可以显示订单笔数，但不显示箱数。

### 3.5 产线订单额排名（全渠道）

- 汇总综合客户和特渠专业客户的有效订单明细。
- 按商品快照 `product_line` 聚合订单额并降序排列。
- 当前大屏展示前 6 条产线，只有订单额，不展示箱数。
- 每条产线使用独立颜色，同一产线在后续模块中保持相同颜色。

### 3.6 下单时间趋势（按小时）

- 使用当前有效订单的 `last_submitted_at` 按小时汇总订单额和订单笔数。
- 修改后的订单归入最后一次提交所在小时，不累计旧版本。
- 查询范围从 `actualStartedAt` 开始；没有实际开始时间时使用 `startsAt`。
- 活动进行中以接口 `dashboard.generatedAt` 作为当前时间；活动截止后使用 `closedAt`，没有实际截止时间时使用 `endsAt`。
- 接口时间桶使用带 `Z` 的 UTC 标准时间，页面统一按照活动配置的时区显示。
- 从活动开始所在小时到当前/截止所在小时连续生成时间点，没有订单的小时补 `0 元 / 0 笔`。
- 零值点准确落在纵轴零线，不因横轴文字改变绘图区高度。
- 曲线使用绿色平滑线、浅绿色面积填充和绿色小圆点。
- 图表默认滚动到最新小时，可按住鼠标或触摸横向拖动，也可使用底部横向滚动条。
- 每个点都可以点击；详情显示活动时区下的完整时间、订单金额和订单笔数，零值点同样可查看。
- 标题右侧显示总小时数和零值小时数。

### 3.7 各渠道产线订单额对比

- 分为“特渠专业客户”和“综合客户”两栏。
- 分别按商品快照 `product_line` 汇总有效订单明细金额。
- 只显示订单额，不展示箱数。
- 产线颜色与全渠道产线排名保持一致。

### 3.8 综合渠道各片区产线订单额明细

- 只统计综合客户，按 `region_code + product_line` 汇总有效订单明细金额。
- 片区卡片顺序跟随当前白名单大区顺序（历史大区使用内部名称字典兜底）；片区标题使用独立片区色，并显示片区订单总额。
- 每个片区内的产线顺序跟随综合渠道全局产线排名。
- 缺失的“片区 + 产线”组合补 0。
- 只显示订单额，不展示箱数；产线颜色与其他产线模块保持一致。

### 3.9 分公司订单额排名 TOP 15

- 按订单中的分公司快照汇总有效订单金额并降序排列。
- 展示名次、分公司名称、订单额和相对金额颜色条，不展示箱数。
- 颜色条高度为 6px，并使用圆角样式提高大屏可读性。
- 排名卡片内部纵向滚动，页面截取并展示前 15 名。

### 3.10 经销商订单额排名 TOP 15

- 按当前有效订单金额降序排列经销商。
- 展示名次、经销商名称、所属分公司、订单额和相对金额颜色条，不展示箱数。
- 颜色条高度为 6px，并使用圆角样式提高大屏可读性。
- 排名卡片内部纵向滚动，页面截取并展示前 15 名。

### 3.11 不区分客户类型模式（待实施）

本节适用于当前活动白名单客户类型全部为空、商品客户类型也全部为空的场景。系统内部使用 `ALL` 表示该模式；当前 H5 已支持直接输入手机号进入订货，但看板及后台相关展示仍需按以下规则适配：

- 活动概览的客户提交进度只显示一条“全部客户／不区分客户类型”进度，不再强行拆分为综合客户和特渠专业客户。
- 订单综合看板隐藏综合/特渠双色渠道占比，改为展示全量有效订单汇总；没有白名单大区时隐藏片区订单分布和片区产线明细。
- 全渠道产线、分公司、经销商和小时趋势继续按当前有效订单统计，不因客户类型为空而丢失数据或重复累计。
- 排行和专题战报不显示综合/特渠专属筛选项、空的类型榜单或误导性客户类型文案，统一使用“全部客户”口径。
- 后台订单、现场到场和抽奖相关筛选及标签不得把 `ALL` 显示成综合或特渠；有类型活动继续保持现有通道规则。
- 该模式优先由当前白名单发布版本的客户类型模式驱动；接口继续使用 `ALL` 及现有订单聚合字段，不通过前端伪造客户类型，也不新增数据库类型值。

## 4. 颜色与布局规范

- 所有白色数据卡标题使用粗体，并在标题前显示对应主题色圆点。
- 产线使用 20 色调色板；前 20 条产线使用不同颜色，超过 20 条后循环使用调色板。
- 产线颜色映射以全渠道产线排名为主，同一产线跨“全渠道排名、渠道对比、片区明细”保持一致。
- 当前白名单实际大区使用独立片区色，与产线色分别管理。
- 金额条以当前模块最大金额为 100% 计算相对长度；金额为 0 时不绘制彩色长度。
- 分公司和经销商排行的金额颜色条为 6px，其他普通金额条按对应模块样式展示。
- 趋势图的纵轴固定在左侧，横轴在独立区域展示，长时间范围通过横向滚动承载。
- 宽屏使用双列及多列卡片布局；窄屏自动切换为单列，页面本身不产生非预期横向溢出。

## 5. 数据接口与字段映射

聚合接口：`GET /screen/activities/{activityCode}/dashboard`。

| 响应字段 | 页面用途 |
| --- | --- |
| `dashboard.totals.total_amount` | 订单总额 |
| `dashboard.totals.total_tons` | 订单总吨数 |
| `dashboard.totals.order_count` | 订单总笔数 |
| `dashboard.totals.dealer_count` | 参与经销商 |
| `dashboard.totals.branch_count` | 参与分公司 |
| `dashboard.totals.sku_count` | 成交 SKU |
| `dashboard.productLines` | 全渠道产线订单额排名 |
| `dashboard.branches` | 分公司订单额 TOP 15 |
| `dashboard.companies` | 经销商订单额 TOP 15 |
| `dashboard.generatedAt` | 快照更新时间和进行中趋势终点 |
| `customerTypes` | 综合/特渠订单额及渠道占比 |
| `generalRegions` | 自描述的综合客户片区数组；包含片区编码、名称、顺序、订单笔数、金额及产线明细 |
| `regions` | 兼容字段：综合客户片区订单额与订单笔数 |
| `generalProductLines` | 综合客户产线订单额 |
| `specialProductLines` | 特渠专业客户产线订单额 |
| `regionProductLines` | 综合客户各片区产线订单额明细 |
| `trend` | UTC小时桶、小时订单额和订单笔数 |

接口仍可能携带其他兼容字段，但订单看板只使用上表字段。所有金额在前端转换为数值后格式化，公开响应不得包含完整手机号。

片区维度由当前生效综合客户白名单和实际订单共同驱动，不写死东区、南区或北区。白名单中的非空大区按稳定编码和白名单顺序返回，暂无订单的片区及“片区 + 产线”组合补 0；遇到历史或异常的未配置片区时使用内部名称字典兜底并追加展示。空大区订单不归入具体片区；当当前白名单没有任何非空大区时，`generalRegions` 返回空数组，前端隐藏片区分布和片区产线明细。片区卡片桌面端每行最多 4 张并自动换行，各卡片共用同一金额刻度，保证横向比较有效。

## 6. 刷新、状态与异常处理

- 首次进入页面立即请求一次完整看板快照。
- 进行中或已截止但整场活动未结束时，收到 SSE `invalidate` 事件后立即刷新。
- SSE 之外保留 15 秒轮询作为兜底，并提供手动刷新按钮。
- 当前小时订单新增、修改、撤回或重新提交后，最后一个趋势点随快照更新。
- 跨入下一个整点后，自动出现新的小时点；没有订单时先显示零值。
- `FINISHED` 或 `ARCHIVED` 状态停止 SSE 和轮询，显示“历史回看”并读取最终 `REPORT` 快照。
- 请求失败时页面保留现有布局并显示“订单看板数据加载失败”等错误提示，后续刷新成功后清除提示。

## 7. 页面顺序

1. 紫色渐变标题栏。
2. 六项核心指标卡片。
3. 渠道订单额占比、综合客户片区订单额分布。
4. 产线订单额排名（全渠道）、下单时间趋势（按小时）。
5. 各渠道产线订单额对比。
6. 综合渠道各片区产线订单额明细。
7. 分公司订单额排名 TOP 15、经销商订单额排名 TOP 15。

当前页面不再展示“各渠道产品线订货箱数”“订货总箱数”“最新有效订单”等旧模块。

## 8. 验收标准

- 新增、修改、撤回、重新提交订单后，SSE 到达时或 15 秒轮询内数据正确变化。
- 六个核心指标能与订单导出按同一有效订单范围复核。
- 渠道、片区、产品线及排行小计不存在重复累计。
- 产线订单额排名、渠道产线对比、片区产线明细、分公司排名和经销商排名均不显示箱数。
- 同一产线在各模块中颜色一致，至少支持 20 种产线配色。
- 所有模块标题为粗体；底部排行颜色条为 6px 且清晰可见。
- 分公司和经销商排名均最多展示15名，内容超出卡片时可以纵向滚动。
- 趋势第一小时不早于活动实际开始所在小时，活动开始前的订单数据不进入统计。
- UTC时间桶按活动时区正确显示，例如 `08:00Z` 在 `Asia/Shanghai` 显示为 `16:00`。
- 趋势连续补齐到当前/截止小时；无订单小时为 `0 元 / 0 笔`，点位落在零轴。
- 趋势图可以横向拖动，每个数据点均可点击查看完整时间、订单金额和订单笔数。
- 手机号、确认人电话等敏感字段不出现在接口和 DOM 中。
- 宽屏投放可正常阅读，窄屏自动改为单列，不出现非预期横向溢出。
- 活动结束后页面显示“历史回看”，刷新不会改变冻结结果。
- 待实施验收：白名单和商品客户类型全部为空时，活动概览只显示“全部客户”提交进度；看板不显示综合/特渠拆分，所有金额、订单数、产线和排行与订单导出全量口径一致。
- 待实施验收：无有效大区时不出现空片区卡片；排行、战报、订单管理、到场和抽奖页面不把 `ALL` 错标为综合或特渠。
