# ADR-009：部门管理员、独立成员与活动数据隔离

- 状态：部门隔离决策继续有效；2026-10-07 扩展为部门管理员与独立成员账号
- 日期：2026-09-02

## 2026-10-07 成员账号扩展

- 每部门仍最多一个 DEPARTMENT_ADMIN（停用也占名额），可创建多个 DEPARTMENT_MEMBER；成员只能属于一个部门。
- 部门管理员管理本部门成员；超级管理员管理全部成员。成员不能管理账号、变更角色或部门。
- 六个模块独立授权：OVERVIEW、PRODUCT、WHITELIST、ATTENDANCE、ORDER、LOTTERY。权限覆盖本部门全部现有和未来活动，不逐场授权。
- 勾选模块即拥有与部门管理员相同的模块业务操作；活动创建、配置、时间、发布、撤回、截止和结束始终仅限管理员。
- 部门管理员密码仍由超级管理员设置、重置；成员密码由部门管理员或超级管理员设置、重置，成员不可自行改密。
- 权限提交后后续请求读取当前权限；停用和重置密码撤销会话，重新启用不恢复旧会话。前端每 15 秒、重新聚焦及收到模块权限拒绝时同步身份并清空旧模块状态。
- 未授权模块不加载明细。订单专用客户/商品查询、聚合计数支持独立模块使用。原有公开 H5/大屏入口继续使用既有规则，模块权限约束后台入口。
- 订单审核、版本、业务操作与审计日志记录实际账号；新记录保存操作时身份，旧共享账号记录不补造个人身份。成员停用后保留历史记录。
- V035 调整部门唯一约束、增加权限表及身份快照字段；已于 2026-10-07 在本机迁移并更新前后端。其他环境需先完成迁移再启用成员功能。
- 成员姓名支持中文、英文或混合，非空且最多 100 字符；登录用户名为 3–64 位，以英文字母或数字开头，其余允许英文字母、数字及 `_ . @ -`，不支持中文。密码 8–100 位。
- 已通过成员专项 API 与组件渲染验证；没有可用浏览器连接，成员功能真实浏览器视觉及交互验收仍待完成，详见 [测试说明](../../../tests/README.md)。

## 原始一期决策（历史背景）

一期采用“一个部门一个后台共享账号”，不细分到部门内个人账号。系统增加 `SUPER_ADMIN` 和 `DEPARTMENT_ADMIN` 两类角色：超级管理员负责创建部门和部门账号，并统一设置/重置部门账号密码；部门账号只访问本部门活动及其业务数据，不能自行修改密码。

每场活动必须归属一个部门。商品、白名单、到场、订单、看板、抽奖、导入文件和审计数据通过活动的 `activity_id` 继承部门范围。部门账号不能通过修改 URL 或子资源 ID 访问其他部门。

部门创建时由服务端根据部门名称生成唯一编码；编码是稳定的部门标识，创建后不可修改，部门名称变更不会重新生成编码。

同一部门的完整活动时间（开始至整场活动结束）不得重叠；不同部门允许同时发布和运行活动。H5、看板、排行、战报和抽奖使用活动编号对应的独立入口，不依赖全系统唯一“当前活动”。

## 一期存量迁移（历史记录）

新增“默认业务部门”（`DEFAULT` / `默认业务部门`），现有活动（包括正在进行中的活动）全部绑定到该部门；原管理员账号升级为超级管理员。迁移不改变活动编号、订单、看板或抽奖数据。

## 一期后果（历史记录）

- 共享账号降低了账号维护成本，但审计只能定位到部门账号、IP 和会话，无法定位部门内部的具体操作者；这是一期明确接受的限制。
- 权限必须在后端按活动归属强制校验，前端菜单隐藏不能作为安全边界。
- 当时预留了个人审计和权限扩展方向；2026-10-07 已通过独立成员账号和六项模块权限落实，当前规则以上文扩展为准。
