# ADR-010：抽奖按需试算、匹配商品小计与资源保护

- 状态：已接受并完成源码及隔离验证，未部署业务服务
- 日期：2026-10-31

## 背景

抽奖与H5下单共用数据库。原规则读取和表单修改会重复计算候选，开奖逐人保存快照增加往返；新增项目组、品种和吨数后，需要统一计算口径并控制昂贵查询的同时执行数量。

## 决策

1. 进入、编辑、切轮、保存和读取规则不计算候选。手动试算只计算当前轮，返回一次完整汇总和名单，弹窗复用响应；正式开奖重新计算最新有效数据。
2. 有效下单范围支持项目组单选与联动品种多选，默认全部；两条件命中同一条有效明细。先限活动、客户类型与有效订单，再按匹配明细一次汇总金额、箱数、吨数，判断所选最低门槛后计算候选总权重。
3. 等概率、金额、箱数、吨数加权四选一。新选择的加权方式联动对应门槛；0仅取消门槛，正权重仍是加权资格要求。用实际小计加权，不扣除门槛、不折算倍数；多奖项按权重不重复抽取。
4. 吨数缺失部分按0计，部分已知按实际合计参与，合计0排除出吨数加权池；不要求补资料，不阻止整轮开奖，不回退等概率。金额/箱数不因吨数缺失排除。保存精度六位，单项或合计NULL在吨数加权中视为0。
5. 试算中的占比表示首位抽中概率，界面称“抽取权重占比”，不充当整轮至少一次中奖率。规则审计记录权重单位和总权重，候选快照保存三项小计；原金额总计字段保持金额单位，结果摘要v2包含箱数。
6. 维持完整候选和中奖记录、轮次行锁、防重与原子事务；候选每批250、中奖批量保存。保留历史配置与结果，复制轮次或重新选择加权方式后使用新绑定关系。V045/V046负责新增字段和模式约束，不回填历史开奖。
7. 每后端实例试算/商品选项默认同时执行2个，开奖独立1个；超额立即503并提示重试，不排队占连接。单条候选/选项查询超时默认8秒，不代表完整开奖事务超时。`.env.example`、Compose与后端默认值同步，实际`.env`可省略这些覆盖值。

## 影响与边界

- 手动试算减少触发次数，并发保护控制峰值，索引和查询计划决定单次读取成本；不为每项筛选无条件增加索引，也不在每次H5下单时维护新的抽奖汇总。
- 无商品筛选的金额/箱数复用现有订单合计，涉及商品或吨数诊断才读明细。本轮沿用既有订单/明细索引，按执行计划和H5混合负载验证。
- 未实现基于最后修改时间的增量候选缓存；完整变化追踪和失效机制不属于本轮范围。
- 多实例名额分别计算，不能把本机2/1名额或短时压测结果直接当作共享数据库全局容量。
- 仅修改示例文件不会影响运行服务。正式发布需配套前后端、V045/V046和部署配置；本次未修改实际`.env`或业务数据库。

## 验证

前端352项、最终抽奖后端专项17项及旧规则原位保存复核通过；1440/440浏览器验证通过。千人在线、每分钟200单的抽奖/不抽奖对照全部提交成功、对账一致，仍有短暂资源等待，不能承诺线上完全无影响。数据、异常尝试、查询计划和边界见[验证记录](../../testing/lottery-weighting-2026-10-31.md)。
