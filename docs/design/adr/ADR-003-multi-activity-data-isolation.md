# ADR-003：单系统支持多活动并按活动隔离数据

- 状态：已接受
- 日期：2026-08-20

## 决策

系统允许创建、运行和保留多场活动历史。每场活动归属一个业务部门；同一部门的已发布且未结束活动完整时间不得重叠，不同部门可以同时运行。活动在 `FINISHED` 结束，超级管理员可手动归档和解除归档；归档沿用原部门与功能权限读取、导出，全部业务写入冻结。归档筛选复用原活动菜单，无新增侧边栏。超级管理员可明确永久删除草稿、已结束、已归档活动：受理即隐藏与封禁访问，后台分批清理，不自动备份、不设回收站；独立任务保留进度和删除凭证。正式 H5、看板、战报和抽奖入口均使用活动编号，通用“当前活动”入口仅作为单活动兼容能力。活动数据按 `activity_id` 隔离，历史数据不被新活动覆盖，共享账号和客户主档不随单场活动删除。

## 约束

- 核心唯一约束必须包含活动 ID；
- 通用 H5 入口由服务端按发布状态和可信时间解析活动，API 从解析结果、令牌或后台上下文取得活动 ID，并验证访问权；
- 缓存键和对象存储键包含活动 ID；
- 禁止把浏览器保存的“当前活动”偏好作为业务数据的权威来源。
