# ADR-002：采用 Spring Boot 模块化单体

- 状态：已接受
- 日期：2026-08-20

## 决策

后端使用 Java 21 + Spring Boot 稳定版本构建模块化单体，MySQL 为唯一业务事实来源。第一期不引入微服务和外部消息队列；当前本地版本由同一个 Spring Boot 进程内的任务执行器处理导入和调度，生产部署目标是拆出独立 Background Worker 并使用 MySQL DB Task Queue。

## 理由

目标规模为千人级同时在线和几百个商品，单体可以满足性能需求；订单、导入和抽奖更需要清晰事务边界。当前同进程运行便于本地开发和交付验证；生产再拆分 Worker 运行角色，可分别扩展 API 和耗时任务，同时保持同一模块和事务设计。

## 后果

模块边界必须在代码包、应用服务和数据库访问层落实。拆分 Worker 不等于拆分微服务；将来只有当统计、导入或抽奖出现独立扩缩容需求时，才进一步按模块边界拆分服务。
