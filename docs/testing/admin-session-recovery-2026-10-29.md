# 后台登录检查容错修复（2026-10-29）

## 问题与修改

`AdminGateway` 每 15 秒、窗口重新聚焦及收到模块权限变化通知时调用 `/admin/me`。原代码在任意请求异常时清空当前账号并卸载工作区；服务器繁忙导致的 500/502/503/504、网络中断或 JSON 解析失败，也会使页面退回登录页，即使数据库里的会话仍然有效。

修复后，上述临时错误保留当前账号和工作区，后续检查继续重试。401 仍清空登录；成功检查发现账号、角色或部门变化时仍清空原工作区；成员权限变化继续同步。没有延长登录有效期，也没有改变后端认证和授权。

## 验证

运行 `node --test tests/admin-session.test.mjs tests/admin-shell.test.mjs tests/department-isolation.test.mjs tests/member-navigation.test.mjs`，31 项通过。

全项目 TypeScript 类型检查和本次修改文件的 ESLint 检查通过。

新增 5 项行为测试覆盖连续检查失败后恢复、窗口聚焦和权限刷新失败、真正的 401、账号/角色/部门变化，以及卸载后迟到的 401。测试使用显式 Hook 状态与定时检查适配器，不等同于真实浏览器或服务器验收。

## 部署与排查边界

本次修改位于本地源码，尚未更新服务器前端。服务器仍需重新构建并发布前端才能使用修复。

用户提供的沟通截图反馈本轮压测将并发上限从 10 提高至 200，应用服务器及数据库 CPU 曾打满，压测结束后仍慢。这与临时服务错误触发误退登录的机制吻合，但未读取目标服务器日志，尚不能据此确认该次掉线的实际响应状态或服务器当前负载。

服务器排查应核对掉线时 `/api/v1/admin/me` 的响应：网络错误或 5xx 可触发原前端缺陷；401 则需核查 Cookie、会话到期/撤销及账号或部门状态。另需检查压测发起端是否完全停止、应用与数据库当前 CPU、活动 SQL、连接占用和锁等待，以确认压测后是否仍有积压。
