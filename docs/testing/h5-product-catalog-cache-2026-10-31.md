# H5 商品目录缓存：实现与隔离验证

## 交付范围

本轮优化 `GET /api/v1/h5/activities/{activityCode}/products` 的重复读取成本。商品、正式图片、阶梯价和可见范围规则在每个后端副本内按活动共用，不保存某位客户的完整响应供其他客户使用。

手机端继续在身份验证后的现有加载流程，以及原有明确重载流程中读取目录。搜索、筛选、加减数量不新增商品或活动查询。此次没有商品 SSE、商品定时刷新、客户端增量目录接口，也不会因后台修改自动覆盖编辑中的购物车。活动资料仍使用已有 SSE；订单和审核状态仍按需查询。

这是待部署源码。仅使用已有 Maven 工具容器、独立临时 MySQL/Redis 和合成资料验证；没有构建或部署业务镜像，没有修改业务数据库，没有重启业务服务。本轮临时测试容器和网络已清理；本记录随代码一并提交，业务环境尚未部署。

## 读取与权限

1. 一条索引查询读取活动、所属部门状态、当前 PRODUCT/WHITELIST 绑定、当前客户行和目录版本。使用当前客户类型、分公司及经销商资料，避免沿用短期身份缓存中的旧权限。
2. 缓存命中时按当前客户过滤不可变商品快照。保留类型/ALL、分公司范围、指定经销商、空/已失效选择拒绝访问、未完善但可展示商品，以及稳定排序等规则。
3. 缓存缺失或版本落后时，同一活动的并发加载合并。加载在独立只读 REPEATABLE_READ 事务中完成；等待该结果的正常 HTTP 请求不占用加载事务或数据库连接。
4. 等待后重新读取客户上下文；如果加载期间目录/名单变化，按新版本重试，最多三轮。缓存版本在上下文读取之后推进时也重新核对，避免误报版本不一致。
5. 分公司和经销商名称使用 MySQL 排序权重保留当前数据库的大小写/重音比较语义。不能简单用 Java 字符串相等替换 SQL 权限规则。
6. `keyword` / `rebateStatus` 等非空服务端筛选参数继续走原 SQL，保留 LIKE 通配符和数据库比较语义。实际手机页面在已加载目录上筛选。

H5 使用独立 `H5Product` 返回结构，去掉品牌/品种、瓶价、吨箱换算系数以及图片 `fileId/sourceType/matchStatus` 等手机目录转换未使用的字段。保留图片 ID/URL/主图/顺序、项目组、价格、阶梯优惠、商品状态、版本及分公司范围。后台商品结构与已有接口保留，订单/草稿/审核接口仍由服务器校验当前状态、权限、价格和订单版本。

响应使用 `Cache-Control: private, no-store`。该服务端共享缓存不授权浏览器、CDN 或代理共用客户响应。

## 修改、事件与恢复

- V043 新增 `activity.product_catalog_version BIGINT NOT NULL DEFAULT 1`。它独立于后台 `activity.version`、单个商品 `lock_version`、导入版本和订单版本。
- 成功新增/修改/删除商品，设置/删除正式图片、确认候选图片，记录受影响的商品 ID。同名商品共享图片时覆盖全部受影响行；排除尚未展示的候选不触发目录变化。
- 未发布的导入预览或 BUILDING 版本不提前影响当前缓存。商品或白名单正式切换绑定时记录完整更新。
- 客户分公司或经销商全名变化、客户增删及白名单发布更新目录版本；纯联系方式编辑不刷新目录。
- 业务修改、目录版本递增、`PRODUCT_CATALOG_CHANGED` outbox 在同一业务事务提交。回滚不留下目录版本或通知；纯订单写入不触发目录更新。
- 维护与发布先锁活动行，统一写入锁顺序。原有商品维护、价格/吨数同步及导入事务边界保留。
- 复用已有 500ms outbox 扫描，从全部原始事件识别目录变化，合并同活动连续版本与商品 ID。即使本批最后一条是订单，也不遗漏目录通知。
- 已知连续变化才部分读取。导入、版本缺口、超过 500 个商品 ID、绑定变化或数据库已推进到通知之后的版本时，重新构建完整快照；不把缺少中间变化的结果标成最新。
- Redis 内部通道 `order-show:product-catalog:v1` 只通知后端副本。重复和旧版本不能覆盖新缓存；订阅恢复清空旧缓存，随后按需重建，避免所有活动同时重载。
- Redis 发布失败只保留目录事件 PENDING，其他已成功处理的事件仍可确认；发布按约 1/2/4/8/16/30 秒退避，重新订阅后可立即恢复。读取端仍查数据库版本，通知遗漏不会造成永久旧缓存。

服务器缓存部分更新不等于向手机推送部分商品。手机下一次按现有流程请求时收到该客户的最新完整可见目录；编辑中的购物车不会静默替换。提交时仍以后端校验为准。

## 每副本资源上限

| 环境变量 | 默认 | 行为 |
| --- | ---: | --- |
| `H5_CATALOG_CACHE_ENABLED` | `true` | `false` 切回原 SQL 路径；保留当前身份检查和精简响应，仍需 V043 |
| `H5_CATALOG_MAX_ACTIVITIES` | 32 | 最多保留活动数，超限淘汰最近最少使用项 |
| `H5_CATALOG_MAX_BYTES` | 33554432 | 估算 32 MiB 缓存预算；按商品及权限内容保守核算，并非 JVM 堆硬上限 |
| `H5_CATALOG_IDLE_SECONDS` | 600 | 空闲淘汰；访问检查加每分钟清理 |
| `H5_CATALOG_MAX_LOADS` | 8 | 所有活动共用的并发加载上限 |
| `H5_CATALOG_MAX_WAITERS` | 512 | 等待加载结果的请求上限，命中请求不占等待名额 |
| `H5_CATALOG_WAIT_MILLIS` | 5000 | 等待超时返回 `503 CATALOG_BUSY`；不取消其他请求共享的加载 |

超预算的单份目录可供当前合并请求使用，但不长期缓存。临时构建对象、正在发送的响应、数据库连接池等不包含在缓存预算中。加载失败释放名额，不覆盖已有成功快照；后续读取按当前版本重试。负载超限不自动切换成大量独立查库请求；由显式配置开关决定是否使用原读取路径。

指标使用 `order_show.h5.catalog.*`，包含 hit/miss、完整/部分加载、加载错误、等待超时、活动数、估算字节、活动加载数、等待人数和淘汰。`stage` 计时区分 context/snapshot/filter，另有请求总计时及慢读取日志。

## 验证

前端 328 项行为测试全部通过；类型检查和修改文件 ESLint 通过。精简响应转换测试覆盖图片主次/排序、项目组、目录字段和两种阶梯价所需资料；原有手动刷新、活动 SSE、购物车及后台测试保留。

最终后端回归为 290 项：222 通过，68 项按其他专项的环境条件跳过，无失败。本轮 `ProductCatalogIntegrationTest` 已启用并通过，使用固定专用测试库验证真实 MySQL、Redis、Tomcat HTTP 和 V043；缓存、权限、通知退避及原有 outbox 测试也全部通过。

真实数据库样例为 606 行商品，覆盖综合/特渠/未区分类型、分公司、指定/空经销商选择、大小写/重音等价、未完善和隐藏商品、主图及阶梯价。各身份新旧读取结果与排序等价。验证回滚、单商品部分更新、同名图片删除、价格/阶梯价变化、Redis 跨副本通知、订阅中断后的数据库版本恢复、名单失效、版本缺口及发布绑定切换。

容量保护测试覆盖 300 个同时读取共用一次加载、等待超时不取消共享任务、加载失败释放容量、并发/等待人数限制、活动数/预算淘汰及过大快照不保留、旧通知和订阅恢复。

### 隔离读取对照

在同一测试库、同一应用中交替执行新旧读取；连接/事务初始化预热后，用 MySQL 会话 Questions 统计各 64 次热读取，排除计数查询自身。测量不包含 HTTP 身份检查、网络传输、页面渲染和 JSON 序列化。响应字节另外用同一应用序列化配置测量，未压缩。

| 指标 | 原 SQL 读取 | 新缓存读取 |
| --- | ---: | ---: |
| 64 次热读取 SQL | 512 | 64 |
| 完整响应字节 | 167719 | 151310 |
| 服务读取 P50 | 7.681ms | 0.485ms |
| 服务读取 P95 | 9.601ms | 0.799ms |

上述记录来自本轮最终隔离测量。300 个并发服务调用覆盖三类客户，共用一次冷目录加载；该次全部结果返回用时 67.190ms。随后逐份与原 SQL 结果比较，不将比较耗时计入冷读取时间。测试使用 Java 21、MySQL 8.4、Redis 7.4，数据库连接池为 8；未据此推算线上最大用户数。

SQL 减少 87.5%，此样例未压缩响应减少约 9.8%。这是本机小型合成目录的读取对照，不是线上混合压测或 Ingress 容量结论，不能据此承诺原报告中的 13 秒慢请求、500/503 已全部消除。商品 GET 仍返回当前客户的完整可见目录。

## 复现

```powershell
node --test tests/*.test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false

# 专用临时 MySQL/Redis：无业务挂载、持久卷或主机端口，不构建镜像。
docker compose -f tests/product-catalog.compose.yml up -d --wait --pull never
docker run --rm --pull never --network order-show-product-catalog-test `
  -e ORDER_SHOW_PRODUCT_CATALOG_TEST=order-show-product-catalog-test `
  -v order-show-m2:/root/.m2 -v "${PWD}:/workspace" -w /workspace/backend `
  maven:3.9.11-eclipse-temurin-21 mvn -o test
docker compose -f tests/product-catalog.compose.yml down
```

集成测试要求空的固定专用库；重复复测前先移除本轮测试容器，再重新启动。测试不接受外部传入的业务数据库地址。日志写在忽略目录 `outputs/`，正式发布时仍需应用 V043、设置各副本参数并按真实商品加载时机复测目标环境。
