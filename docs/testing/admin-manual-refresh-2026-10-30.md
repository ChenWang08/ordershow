# 后台取消常驻轮询（2026-10-30）

> 历史验证记录。2026-11-01 源码已改为每次进入模块自动读取，概览自动加载统计，精简刷新入口并取消活动/浏览器离开确认；以下旧交互和测试数量不代表最新行为，见[后台进入加载验证](admin-entry-refresh-2026-11-01.md)。空闲不轮询原则继续保留。

## 范围与交互

仅调整后台五类刷新，不修改后端 API、数据库、H5 下单、三个展示大屏或抽奖现场的刷新策略。

| 模块 | 新行为 |
| --- | --- |
| 活动概览 | 初次进入不查询排行和提交进度。点击“刷新统计”才读取三组排行和模块人数，全部成功后一起显示；切换后台模块保留快照，切换活动或整页刷新后恢复未加载。 |
| 模块基础信息 | 进入商品、白名单、到场、抽奖规则等相关模块时加载；白名单及到场操作成功后失效重读；提供“刷新基础信息”。不在概览空闲时查询。 |
| 订单变更审核 | 进入审核页、筛选/翻页、手动刷新及审核结束后查询。订单列表不再后台轮询申请。未加载的待审核数量显示“—”。 |
| 活动信息 | 后台不再每 15 秒查询；必要初始化、活动操作返回值更新以及“刷新活动信息”保留。有未保存活动设置时，刷新前必须确认；查询失败保留草稿。 |
| 登录身份 | 不再定时查询 me。首次检查、窗口聚焦检查（短时间去重）、权限异常检查保留。401 统一失效处理，包括写操作和导出；一般业务 403、网络错误及 5xx 不触发退出登录。 |

统计快照只保存在本次页面内存中，不持久化到本地；其他人的订单、申请、配置变化需要手动刷新或重新进入相应模块获取。

`useAdminQuery` 统一提供重复点击合并、切换/卸载取消、旧响应隔离、失败保留数据及成功时间。统计错误还会中止该轮其他未完成查询，避免失败后重试叠加。

共用 `useActivityRuntime` 仅在存在 `adminActivityId` 时跳过周期查询。公开页面的活动轮询不变。导入任务等待、抽奖资格试算、本地时间控件定时器及服务端活动生命周期任务均保留。
