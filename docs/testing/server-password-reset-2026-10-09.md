# 服务器重置超级管理员密码（2026-10-09）

## 认证与一致性

后台使用随机 Cookie `ORDER_SHOW_ADMIN_SESSION`，令牌及 CSRF 令牌的 SHA-256 哈希保存在 MySQL `admin_session`。每个新请求查库校验撤销、过期和账号状态；principal 仅在同一请求复用。没有 JWT、Refresh Token、续期接口或 Redis 登录缓存。

命令复用 BCrypt（强度 12）及现有数据库配置，不启动 SpringApplication、Web、迁移或定时任务，不新增依赖、字段或公开接口。首次初始化强制改密不变。

密码更新、清除目标账号强制改密标记、撤销全部旧会话及同步审计使用同一 MySQL 事务。只有提交返回成功后才输出成功；连接或提交异常报告“未确认重置成功”，应恢复连接并核对登录/审计后再重试。

登录从密码校验至会话签发持有账号行锁，重置使用同一锁：旧登录先提交时，新建会话被后续重置撤销；重置先提交时，等待中的旧密码登录被拒绝。主动改密也使用事务及账号锁，等待后重新检查会话，避免已撤销请求覆盖重置结果。主动改密保留当前浏览器会话，服务器重置撤销全部旧会话。

已在重置提交前通过认证的在途请求可能完成；提交后的新认证请求拒绝旧凭证，不承诺撤回已执行操作。

## 使用

本地：`.\scripts\reset-super-admin-password.ps1`。
Linux：`sh scripts/reset-super-admin-password.sh`。

命令确认唯一超级管理员，不提供账号选择。核对实际数据库与账号后，明文输入两次新密码；重置不启用停用账号、不修改 .env、不触碰订单和其他账号。数据库提交结果不确定时，先尝试新密码登录及检查 ADMIN_PASSWORD_SERVER_RESET 审计，再重试；同一新密码已生效时会拒绝重复设置。

具体环境参数和故障处理见 README。功能首次安装需更新后端，以后日常重置不需构建、部署或重启业务服务。开发验收不重置本机业务超级管理员密码。
