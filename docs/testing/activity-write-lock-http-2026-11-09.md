## 范围与业务边界

统一拦截器原先对所有管理端活动写入口取得活动排他锁。候选预览、订单试算虽然归入 `readOnly`，该变量仅控制归档活动访问，没有改变锁模式。2026-11-06 的审核修复位于服务层，HTTP 外层仍先取得排他锁，原服务层并发测试无法发现该遗漏。

仅对以下四类 POST 路由在统一入口改用活动共享锁：

| 路由后缀 | 保留的保护 |
| --- | --- |
| `lottery/candidates/preview` | 活动状态/配置就绪检查、原候选资格与权重计算 |
| `orders/preview` | 活动状态、客户与商品校验、原价格和吨数计算 |
| `order-change-requests/{requestId}/approve` | 活动共享锁、客户独占锁、申请/订单版本与幂等、历史和汇总写入 |
| `order-change-requests/{requestId}/reject` | 活动共享锁、客户独占锁、申请状态与幂等、操作记录 |

保留原 READ COMMITTED 外层事务，活动状态检查与业务处理仍处于同一事务；`allowArchiveRead` 与共享/排他锁选择独立。原有抽奖预览可查看已归档活动，订单试算与审核继续拒绝已归档活动；已请求删除及配置未就绪的活动仍拒绝访问。

正式开奖、调价、归档/解归档、永久删除、后台直接建单/调单/作废及其余后台写入口继续保留排他锁。H5、草稿自有事务和导入失败记录的事务边界保持原样。无新 SQL 迁移、配置参数、连接池、定时任务或临时文件；本地和 ACK 共享同一业务代码，MinIO/OSS 选择方式不变。

预览是查询时点的数据，H5 并发提交后下一次预览可见新数据；正式开奖继续重新计算并保存候选/中奖快照。此项消除的是四个入口不必要的活动排他锁，仍存在数据库 CPU、连接、其他行锁及排他请求排队等竞争。
