## 2. 本轮真实端到端覆盖

隔离 API 场景不是源码字符串检查，而是连接实际启动的 Spring Boot、MySQL、Redis 和 MinIO：

1. 空测试库执行 V001-V011，健康检查返回 UP；
2. 未登录管理员接口返回 401，首次登录强制改密，写请求校验 CSRF；
3. 创建草稿活动，无商品/白名单时禁止发布；
4. 内存生成并上传真实 XLSX，完成 5 条商品、6 条白名单和 3 条到场记录的预览与发布；
5. 验证综合/特渠同手机号合法、H5 身份绑定和各自商品目录隔离；
6. 保存并读取按活动客户隔离的购物车草稿，拒绝伪造其他客户 ID，校验草稿基线版本冲突；订单首次提交 V1 后清除草稿，并继续验证幂等重放、幂等键不同载荷冲突、修改 V2、旧版本冲突、撤回和重新提交 V3；
7. 验证金额、吨数、订单号不变、版本/操作轨迹、撤回排除看板、重提恢复统计；
8. 验证后台分页、订单详情、手机号脱敏和 Excel 导出；
9. 验证到场全称匹配、同分公司简称匹配、未匹配排除和管理员明文电话权限；
10. 验证全部客户、有效订单、现场到场三类抽奖候选；
11. 10 路并发开奖只有一个请求成功，只生成一份结果；
12. 验证完成、无理由重置拒绝、有理由重置、中奖失效统计和公开抽奖脱敏；
13. 草稿 `updatedAt` 必须落在当前 UTC 时间附近，页面固定按 `Asia/Shanghai` 显示，防止重复增加 8 小时；

## 5. 执行中修正记录

本轮草稿功能试跑发现并修正以下问题：

- 管理员首次登录时，强制改密检查先于普通写请求 CSRF 检查；
- 已登录管理员的白名单/到场管理接口按设计允许显示完整电话，公开/H5/订单/大屏接口才要求脱敏。
- JDBC 对 MySQL `DATETIME` 返回 `LocalDateTime`，草稿映射已同时兼容 `LocalDateTime`、`Timestamp` 和 `Instant`；
- MySQL 容器使用 `Asia/Shanghai`，早期草稿默认时间被后端误当成 UTC，浏览器再次加 8 小时。V011 已校正明显未来的旧值，后续写入显式使用 `UTC_TIMESTAMP(3)`，页面显式使用 `Asia/Shanghai`。

修正后执行完整回归，最终结果为 37/37 通过。
