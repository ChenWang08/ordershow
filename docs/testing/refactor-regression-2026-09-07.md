## 回归发现的既有问题（未混入业务重构）

首次 API E2E 在到场全称匹配处失败：预期匹配 2 人，实际 1 人。

原因：`ImportService.normalize` 会删除下划线，而 `AttendanceMatchingService.normalize` 只删除空白并转小写。测试客户 `AUTOTEST_综合经销商一` 导入后的标准化字段不含下划线，到场全称查找仍含下划线，因此无法匹配。相关导入和匹配业务代码在本轮没有修改。

测试修正：把测试客户名称的人工前缀改为 `AUTOTEST综合经销商…`，同步更新引用和搜索样本；保留“全称匹配 + 同分公司简称匹配 + 无匹配”、匹配人数及并发开奖全部原有断言。修正后重建隔离环境，50 项后端测试全部通过。

**这不是业务缺陷已修复的证明。** 实际经销商名称含下划线等标点时仍可能遇到标准化不一致，需要另行统一名称规则并回归，本轮为保持业务行为没有修改这部分逻辑。
