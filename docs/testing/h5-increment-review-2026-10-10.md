# H5 增量直提与减量审核（2026-10-10）

## 实现规则

- 首次订货、有效订单纯增量（增加数量/新增商品）直接生效。
- 以当前有效订单逐商品比较；任一商品减量或删除即整次审核，不以总箱数或总金额判断。
- 整单撤回需审核，审核前原订单仍有效。
- 已撤回、已作废订单重新提交直接恢复，不比较失效前数量，沿用订单 ID 和订单号，生成新版本。
- 商品、数量完全未变时不更新订单，不产生申请，也不取消旧待审核申请。
- 新的减量申请替代旧申请；纯增量或恢复成功后旧待审核申请自动失效，沿用 REJECTED 状态并记录原因；提交失败保持原状态。
- 后台操作继续直接生效；订货时间、活动、客户身份、商品范围和权限限制保持。

## 实现与兼容性

后端订单 PUT 校验减量并拒绝绕过审核；审核申请接口拒绝纯增量及失效订单恢复。H5 根据同一规则选择接口并展示对应按钮与提示。

新 H5 同时提交 expectedVersion 与 expectedLockVersion，防止管理员作废/审核撤回后，旧页面在版本号未变时误覆盖状态。锁版本纳入幂等指纹及浏览器重试存储；省略锁版本的旧命令保留原指纹兼容性。

订单写入、历史版本、旧申请失效、草稿清理和通知事件在同一事务内完成。恢复统一使用现有 RESUBMIT 操作类型，原因区分恢复已撤回/已作废订单；清除当前失效状态字段并保留历史。无需新增数据库迁移。

## 回归覆盖

- 前端：逐商品判定、混合增减、无变化保留旧申请、两种失效订单的编辑入口及恢复、待撤回期间继续增量、直接提交清除旧申请展示、重试携带同一幂等键和锁版本。
- 真实 API：增量更新及重放、混合减量拦截、无效商品提交保留原申请、无变化不新增版本、新增量使旧申请失效且不能再通过、删除商品审核驳回、撤回后少量重新订货、管理员作废后少量重新订货、旧锁版本冲突、恢复后订单号/ID/历史和排行统计。
- 既有审核申请替代、审核通过、截止限制、账号权限等回归继续运行；旧用例中的纯增量审核夹具改为减量，恢复夹具改为直接提交。
