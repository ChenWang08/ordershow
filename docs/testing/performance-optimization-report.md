## 实施内容

1. 商品目录的图片、分公司范围、阶梯价格按授权后的商品ID批量查询，每批最多500个ID。300商品的附属查询由约900次降为3次；筛选、排序及商品字段保持不变。
2. 订单历史明细批量查询，每批最多500个版本。历史/操作列表的权限校验不再先加载完整详情，避免重复读取。
3. H5 GET/PUT订单和撤回接口新增可选`includeHistory=false`，跳过历史和操作记录的数据库读取，返回空数组；默认true兼容旧客户端。H5前端已使用false，管理员详情和历史接口保持原行为。
4. H5提交、撤回和草稿采用活动共享锁→客户独占锁→订单/幂等记录的顺序。不同客户可并行，同客户首次提交也有已存在的客户行可锁。调价、管理员订单维护继续使用活动独占锁；截止的活动UPDATE也需要独占锁。
5. 写事务使用READ_COMMITTED，等待锁后重新校验活动状态；当前订单GET使用只读一致性快照，避免主表与明细跨版本读取。
6. 复测发现活动查询仍反复组装大区和白名单类型，增加了数据库负载。新增内部orderingActivity只查ID/截止时间；写入状态校验只读取状态和时间窗口，复用原effectiveStatus规则，避免在下单、草稿、查单、商品查询中重复扫描白名单。公开活动/后台活动接口保留完整信息。

共享锁与独占锁互斥的数据库语义见[MySQL官方锁定读取说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。本轮未扩大数据库连接池、CPU或内存限额，未增加缓存过期一致性问题。
