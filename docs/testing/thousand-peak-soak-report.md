## SSE通知问题

千人场景之后的100连接SSE专项超时。只读检查发现测试订单事件82879在03:19:55.505 UTC创建，03:21:17.972才标记发布，延迟82.467秒，说明存在事件发布积压。
随后低负载检查时队列已降至个位数、最老待发布事件年龄0秒。API下单与数据正确性通过，不能因此宣称实时通知也通过。
该问题保留为失败项；本轮不修改业务实现。队列此前经历了200用户高频负载，因此不能只把积压归因于一分钟千人场景。
长稳中多次只读采样，待发布事件为个位/十余条，最老事件年龄不足1秒。长稳后的100连接专项全部收到通知，P95 323.14ms、最大323.29ms，通过。
前后SSE均为独立短专项，没有保持100连接整整60分钟。建议下一步检查事件发布吞吐、批量更新发布状态及同活动刷新通知合并，再复测高负载后的看板实时性。
