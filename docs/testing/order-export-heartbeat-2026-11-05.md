# 订单导出 EXPORT_STOPPED 排查与修复

日期：2026-11-05（北京时间）。本记录对应 ACK 工作树源码，尚未构建或部署修复镜像。

## 用户现场

任务 1、活动 10，`cancelRequested=false`，记录 4897 单、111702 条明细；北京时间 19:13:27.871 创建、19:13:45.258 失败，相隔 17.387 秒。返回 `EXPORT_STOPPED`，提示“导出已取消或执行许可已失效”。HTTP 202 表示创建任务成功，后续 HTTP 200 只表示成功读取任务状态，不能说明后台已成功生成文件。

再次尝试的任务 4 同样未请求取消：北京时间 19:35:22.305 创建、19:35:38.160 失败，相隔 15.855 秒，停止前记录 4897 单、566853 条明细，仍为 `EXPORT_STOPPED`。两次明细计数仅代表各自停止前的进度，不代表活动的最终明细总量。现场请求头属于查询任务记录的 GET，不是 ZIP 下载；该请求 HTTP 200 及约 7 毫秒的上游响应时间不能用于判断后台生成是否成功，也不能证明触发了网关文件大小限制。

未取得该现场的 worker 日志，因此不把本地复现当作云端异常堆栈的直接证据。以下缺陷能够产生相同失败码、未取消标记和相近时间窗口。

后续截图显示另一活动任务 2 导出成功：1501 单、203553 条明细、226 行有效商品及 54 行有效分公司。因此不能把现场失败解释为明细行数上限。此缺陷取决于读取事务占用控制连接的时长；订单分布、分批查询、汇总耗时及当时负载都影响该时长。总导出时间还包含读取事务结束后的压缩和上传，不能仅按总耗时判断是否触发。

## 已复现的缺陷

worker 的读取池和控制池分别最多 1 连接。CSV 使用读取池的长时间重复读事务，进度回调使用控制池校验活动并更新任务。读取事务管理器默认启用 Spring 事务连接同步，导致控制池连接也被绑定到当前线程，直至整个读取事务结束才释放。

第 10 秒心跳线程尝试借用控制池唯一连接；连接仍被读取线程占用，等待 5 秒超时。原心跳捕获异常后只设置停止标记，下一进度检查把任务记为 `EXPORT_STOPPED`。这可以发生在 90 秒许可实际过期之前。`orderCount`、`detailCount` 只是最近一次成功写入的进度，失败时 `sheetCounts=[]` 表示任务没有发布完整结果。

原有导出集成测试使用可创建多个连接的数据源，大数据生成用例未连接真实进度回调；因此未覆盖“各池仅 1 连接且读取跨越首次心跳”的情况。

## 修复

- 仅对 worker 专用读取事务管理器设置 `SYNCHRONIZATION_NEVER`，避免将控制池连接同步绑定到 CSV 读取事务。读取池连接仍由真实数据库事务管理，保持重复读快照。
- 心跳异常日志记录任务编号及底层异常，便于区分连接获取失败与许可校验不通过。
- 不增加连接池大小，不改变全局任务领取、许可令牌、过期接管、取消、临时文件或 MinIO/OSS 配置。worker 连接预算仍为 2，无新增 SQL、Java 数据迁移或部署配置项，现有模板继续适用。

## 隔离验证

仅使用 `deploy/verify/compose.yaml` 的 `order-show-ack-smoke` 项目，真实 MySQL 8.4、MinIO，以及各限 1 连接的 Hikari 池。测试 JVM 堆上限 256 MiB。

- 修复前 2 项回归均失败：读取内并发心跳报控制连接获取超时；强制保持读取 16 秒的真实 runner 以 `FAILED / EXPORT_STOPPED` 结束，实测约 16.169 秒。
- 修复后 `ExportHeartbeatIntegrationTest` 2 项、`CsvFileTest` 3 项，合计 **5 项通过、0 失败、0 错误、0 跳过**。
- 读取事务内执行真实进度/活动校验后，另一个线程仍可通过唯一控制连接续期；控制连接归还池中，读取连接仍被事务持有。另一个连接修改活动后，读取连接仍看到修改前的值，证实重复读快照保留。
- 同样强制读取 16 秒的真实 runner 成功生成并通过 MinIO 上传、读取 ZIP，实测约 **18.099 秒**，状态 `COMPLETED`；四表行数正确，临时目录已清理。该用例以空订单数据和人为延长读取精确覆盖连接占用窗口，不是原活动数据重放或吞吐基准。
- 同一用例同时确认：过期许可不能续期；新执行者取得不同令牌；旧执行者不能写进度或发布结果；新许可可续期；取消后续期和进度更新被拒绝。
- `git diff --check` 通过。未运行全项目回归或真实云端验收。

复现/回归类为 `ExportHeartbeatIntegrationTest`，仅在 `ACK_EXPORT_HEARTBEAT_TEST=ack-smoke-only` 时启用，固定连接隔离网络内的 `mysql:3306/ack_smoke` 和 `minio:9000`；不会清理或连接业务数据库。先启动 smoke 的 mysql/minio 服务，再在同一 Docker 网络运行 Maven：

```text

mvn -o -f backend/pom.xml -Dtest=ExportHeartbeatIntegrationTest,CsvFileTest -DargLine=-Xmx256m test
```

本机原始日志与报告位于 Git 忽略目录 `outputs/export-heartbeat-20261105/`。原业务容器未启动、修改或重启；没有执行云端 SQL、上传镜像或修改现有交付包。

## 发布与待验

现有 `20261105.1` 镜像不含本修复。后续应构建新版本后端镜像并更新 export-worker；不需要仅为本修复更新前端或数据库。部署后通过“导出订单”创建新任务，原失败任务保留历史状态。增加 API 业务连接池不改变 worker 的专用控制池，不能替代本修复。
