# 手动新增白名单与表单保存提示回归

日期：2026-10-19（北京时间）。

## 原因与修改

白名单新增的 `activity_customer` 插入语句在自动序号子查询前有 18 个占位符，但该部分只有 17 个字段值。实际共 22 个占位符、21 个参数，运行报 `No value specified for parameter 22`。已删除多余占位符，保留原事务、校验、当前版本绑定及到场重新关联逻辑。

商品、白名单和到场表单原先只接收布尔保存结果，详细错误交给被抽屉遮住的页面提示。现在统一接收 `DrawerSaveResult`，具体原因在抽屉内以 `role="alert"` 显示，支持换行和窄屏布局。成功才关闭；失败保留输入。共享保存守卫阻止同时重复提交。

商品资料保存成功后，图片处理或目录刷新失败，会同步已保存记录的 ID/版本并明确提示已保存。导入预览写入成功但刷新失败也有对应提示。部分完成、未知新增结果和服务端 5xx 的新增失败要求先刷新核对，当前抽屉禁用再次保存并提供刷新入口；没有引入新增请求自动重试或后端幂等协议。

## 实测结果

- 修复前：在 8180 隔离服务上用合成 Excel 建立活动，手动新增白名单稳定返回 500，专项脚本在首次新增断言处失败。
- 修复后前端：218 项测试全部通过；类型检查、全项目 ESLint、生产构建通过。其中新增 9 项行为测试，覆盖真实错误传递、新增结果未知、预览刷新失败、服务端 ID/版本回显、商品部分保存及重复提交保护。三个既有抽屉交互测试补充具体错误展示断言。
- 后端：184 项，167 项通过、17 项按环境条件跳过，无失败；包含原有隔离 API E2E。未将跳过项计为通过。
- 新增专项 API：96 项响应状态断言，另验证字段、身份和数量。综合/特渠及不区分类型、空选填字段、同渠道重复手机号/身份拒绝、跨渠道同手机号、纠正数据后重试、基础和阶梯/指定客户商品、到场已关联、待确认与未关联、订货中原因必填、待开始和截止限制、活动隔离、新客户 H5 验证通过。
- 部门权限脚本：144 项 API 断言通过，覆盖六模块和跨部门权限，以及原有订单操作流程。
- 专项真实浏览器：三个抽屉分别验证详细业务错误、390×844 下长错误可见、输入保留后向真实 API 重试成功、网络中断后禁止直接重复新增；另验证商品已创建但图片处理 500 时数据库仅有一条记录。1440×1000 桌面检查通过，无未捕获页面错误。
- 本机更新后：后台登录页和“测试5”H5 双通道入口加载通过，未进行真实客户验证、添加或订单提交。

上述新增和故障模拟全部在 `order-show-e2e` 隔离栈进行。本次未在“测试5”写入测试数据，也未添加截图中的客户。

## 复跑

完整隔离测试入口为 `scripts/run-automated-tests.ps1 -KeepEnvironment`；新增 API 脚本已接在部门权限测试后。专项脚本也可在隔离服务准备好后单独运行：

```powershell
node scripts/test-manual-additions.mjs
$env:ORDER_SHOW_E2E = 'order-show-e2e'
# 如项目未安装 Playwright，指定本机可用包的 index.mjs 文件 URL。
# $env:ORDER_SHOW_PLAYWRIGHT_MODULE = 'file:///.../playwright-core/index.mjs'
node scripts/test-manual-additions-browser.mjs
```

脚本固定访问 8180/3100，不接受业务 URL；合成夹具和截图写入被 Git 忽略的 `outputs/manual-additions/`。Java E2E 需要初始隔离账号，整套复跑前按原测试说明重置隔离栈；专项脚本自身支持已改密的隔离账号。清理用 `scripts/test-env.ps1 reset`。

本次用行为测试替换三条依赖旧布尔返回值和局部变量名称的源码断言。测试范围不包含压测、全浏览器兼容性、真实业务客户补录或服务器部署。
