# 白名单、现场到场分页验证（2026-11-10）

## 范围与发布状态

仅修改两个后台已发布名单的读取与维护：白名单、现场到场。默认每页 50 条，可选 20/100；页面进入、翻页、改变筛选时只读取所需页，不再循环下载全部分页，导入完成后的回读也走分页刷新。

商品列表、经销商候选缓存、商品下单范围、H5 商品、手动抽奖试算使用原有流程。Excel 预览继续完整解析和服务端校验，与已发布名单的分页状态分开。抽奖资格及结果仍由服务端完整数据计算。

这是待发布源码，不包含在既有 `20261110.1` 后端和 `20261106.1` 前端镜像中。本次只构建本机隔离测试镜像，未上传镜像、未部署真实 ACK、未执行云端 SQL。

## 实现与兼容边界

- 新增 `customers/page`、`attendees/page`：当前页数据、筛选后的分页总数、整份名单汇总、完整筛选选项和当前页记录版本一起返回。每页最多 100 条。数据库使用一致的只读事务，白名单按 Excel 序号和 ID、到场按 ID 倒序稳定分页。
- 顶部统计不再用当前页数组长度；到场资格客户按客户 ID 去重。筛选无结果时保留已发布状态；清空名单后也根据已发布数据绑定区分“已发布空名单”和“未导入”。
- 搜索在服务端处理完整名单；支持名称、姓名、电话号码、到场分公司及参会人员类型等原有搜索内容。部分手机号搜索兼容加密历史值，会在服务端检查候选加密值；大量真实数据下的搜索耗时仍需云端评估。
- 已选 ID 与不透明版本跨页保留；筛选条件改变时清空选择。选择全部筛选结果后可排除个别记录。选择、取消勾选本身不请求整份名单。
- `deletion-preview` 返回实际数量及 SHA-256 确认快照；`batch-delete` 在事务内锁定活动、所选记录并重新核对快照。并发修改、删除或导入换版时返回 `ROSTER_CHANGED`，不部分删除。快照及选择参数不依赖 Pod 内存，可跨副本提交；重复确认不会继续删除新记录。
- 白名单删除仍仅限草稿，保留历史订单、撤销对应 H5 会话、重新关联到场记录、更新活动及商品目录变更记录。到场名单截止、结束或归档后禁止删除。旧单条到场删除补齐事务与活动锁，避免与活动截止并发穿透。
- 新增、编辑、删除成功后刷新当前页与统计；末页删除后页码自动回到有效页。全局重复关系由服务端最终检查，本页提示不作为全局唯一性的保证；服务端继续生成白名单序号。
- 原 `customers`、`attendees`、订单客户选择、单条维护接口继续兼容旧前端；没有修改订单/H5 读取协议。新前端依赖新增接口，发布必须先升级所有 API 后端副本，再升级前端；回滚先回滚前端。

## 复跑

先使用当前源码构建前后端测试镜像并按 `deploy/verify/compose.yaml` 启动隔离 API 双副本及前端；务必显式选择当前镜像标签，Compose 默认的旧交付镜像不含新增分页接口。

```powershell
npm run typecheck
npm run lint
npm run build
node --test tests/*.test.mjs

# 在 Maven/JDK 21 环境执行；本地可使用一次性 Maven 容器和已有缓存。
mvn -f backend/pom.xml '-Dtest=RosterServiceTest,MemberPermissionServiceTest,AttendanceMatchingServiceTest,AttendanceMatchPreviewTest' test

node scripts/test-ack-roster-pagination.mjs --ack-smoke
node scripts/test-ack-roster-boundaries.mjs --ack-smoke
# 配置 ORDER_SHOW_PLAYWRIGHT_MODULE / ORDER_SHOW_BROWSER_PATH 指向本机可用的测试浏览器。
# 18031 须空闲，脚本在该端口建立临时代理，转发至隔离 API 及 18030 前端。
node scripts/test-ack-roster-browser.mjs --ack-smoke
```

三个 ACK 脚本固定隔离项目、数据库或本机端口，不接受业务 URL。它们创建专用合成活动，不修改其他业务活动；边界脚本仅将自己新建的活动改为截止状态以验证限制。浏览器脚本会修改并删除合成夹具中的到场记录，可以重复运行。
