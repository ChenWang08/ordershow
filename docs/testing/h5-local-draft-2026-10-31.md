# H5 本机草稿与抽奖按页面加载验证（2026-10-31）

## 范围与实现

- 购物车加减、输入、删除/清空、阶梯价和确认预览在前端内存计算；800ms 防抖写入 `localStorage`，同一快照不重复写。页面隐藏、卸载、切换客户和退出直播间只补存本机，不发送 `order-draft` GET/PUT/DELETE，也不在最终确认前向草稿接口提交。
- 旧后台草稿不读取、不迁移；后端兼容接口和历史表保留，无数据库迁移。正式提交/变更申请使用原接口及幂等/版本校验。
- 本机记录格式版本 1，键由活动 ID、活动编号、客户 ID 组成；仅保存商品 ID/数量、订单/申请基准及毫秒保存/失效时间。最长 7 天且不超过保存时订货截止时间；过期/损坏记录按需清理，截止/结束不恢复。恢复提示固定北京时间。
- 验证后先读取当前目录、订单/申请，再比较订单 ID、业务版本、锁版本、状态以及申请 ID、类型、状态、版本、商品数量和申请/审核时间。管理员调整、审核及同申请 ID 的状态/内容变化均使旧草稿失效，明确提示。仍有效的待审核/驳回修改可继续编辑；不可订商品从本机草稿移除并提示，价格从当前目录计算。
- 编辑中不因聚焦或其他标签页的存储变化替换购物车。订单详情按需刷新、15 秒冷却、同客户在途合并、编辑/撤回前必要检查保留；活动资料继续独立 SSE，无商品/订单 SSE 新增。
- 成功提交/申请后清理本机草稿，取消旧定时器/快照，防止页面隐藏时重新保存旧内容。提交/重新加载失败保留修改。提交结果未确认时不恢复可编辑草稿，不允许继续加减；仍用原 `sessionStorage` 幂等命令确认结果。
- 本机存储禁用、不可读或写满时可继续内存编辑和提交，提示刷新/关闭可能丢失，不回退到后台自动保存。客户切换不依赖网络草稿完成；每个身份草稿隔离，失败时可暂存于当前 H5 实例内存。退出直播间时若本机保存失败需确认。
- `useActivityRuntime` 移除公共抽奖资料加载；H5、活动资料初始化和切换活动不查询抽奖。实际 `LotteryBoard` 原有独立轮次/结果加载及操作流程保留。

## 验证结果

### Node 行为测试

直接执行 `node --test tests/*.test.mjs`：**342 项通过，0 失败**，未调用 `npm test` 的前端构建步骤。涵盖本轮与既有前端测试，包括：

1. 本机草稿跨存储实例恢复，活动/客户隔离，不保存价格或凭据；损坏/格式不支持/非法数量/重复商品/过期/截止提前的处理。
2. 快速输入合并为一次本机保存，隐藏/卸载补存，清空购物车的有效修改可保存；本机禁用/写满时保留内存并可在存储恢复后重试。
3. 首次进入先读最新订单及申请，不读旧后台草稿；业务版本/锁版本/状态/订单 ID/申请状态和内容变化后的草稿失效。
4. 普通与待审核静置 65 秒无订单查询；订单刷新冷却、共享查询和强制编辑前检查保留。审核通过及管理员直接修改后使用最新购物车，编辑中返回不覆盖。
5. 改数量、确认预览/返回、隐藏/显示及返回直播间没有草稿 HTTP；切换客户保存旧客户、恢复各自内容。
6. 返回原数量清理；提交失败/重新加载失败保留，确认成功/申请成功清理且不会由旧快照复活；结果不确定先恢复原提交。
7. H5/公共活动不查询抽奖，活动切换正确关闭旧 SSE；实际抽奖页的加载、回看、执行、重试与迟到响应处理通过。

全项目 TypeScript 类型检查通过；修改的前端、脚本和测试文件 ESLint 通过。

## 边界

仅前端源码、测试及文档；未构建/部署业务镜像、重启业务服务、写业务库或推送 Git。微信内置浏览器同样使用站点 `localStorage`，但本轮浏览器测试使用桌面 Edge 的两种视口，未在真机微信验收。草稿仅属于当前设备/浏览器，清理站点存储会丢失，页面内存不能跨关闭保存。

本轮确认取消了草稿自动 HTTP 和订货入口的抽奖读取，没有进行服务器并发压测，不给出延迟改善比例或 1000 用户容量结论。商品目录缓存和活动 SSE 的部署要求仍以各自文档为准。
