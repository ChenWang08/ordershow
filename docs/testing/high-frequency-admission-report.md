# H5高频写入隔离优化与复测（2026-09-10）

## 结论

200用户持续高频场景已通过原门槛；500用户读取通过但写入延迟未通过，因此按规则未执行1000用户持续高频。千人正常峰值重新通过。最新变更仅完成20流程/秒3分钟长稳预检，没有再次执行60分钟；2026-09-08最终版本的完整60分钟记录继续保留，但不能替代本次候选的完整一小时验证。

所有负载均在固定隔离项目中执行，业务环境只在测试和回归完成后更新。后端2CPU/1280MiB、MySQL1.5CPU/1GiB；最终配置为数据库连接池20、H5写入许可12，不降低MySQL持久化设置、不放宽P95/P99和错误率门槛。

## 实施

- 开启Java 21虚拟线程，使等待写入许可的H5请求不长期占用平台线程。
- H5订单、撤回和草稿写入增加公平的有界并发入口，默认12个许可、等待上限12秒；超时返回带Retry-After的503。GET读取、后台写入和公开验证不经过此入口。
- 20连接池中最多12个H5写事务竞争连接，为身份、商品和订单读取保留容量；暴露active/waiting监控指标。
- 审计批量写入的`synchronized`改为ReentrantLock，避免虚拟线程在数据库I/O期间固定载体线程。审计仍同步等待、保持原范围和失败语义。
- 压测工具支持独立项目、端口、结果目录和后端镜像；新增夹具会话/活动窗口续期脚本，只修改隔离测试环境，不修改订单和版本。

## 夹具过期与无效实验

9月10日首次复跑发现9月8日创建的6247条测试会话过期，随后确认LOAD-1/LOAD-2也已截止。对应`mixed-200-1789006652220`和`mixed-200-1789006753042`分别为401/409夹具失败，不作为性能结论；原结果保留。续期后订单数4278、版本数330747保持不变。

## 500用户与中止规则

12许可、20连接的`mixed-500-1789009362228`运行5分钟：126580请求无错误，31645次提交和63290条审计全部一致；读取P95 81.96ms通过，但写入P95 3287.77ms、P99 3881.55ms，超过1500/3000ms门槛，失败。

有证据显示CPU尚有余量后，另建全新环境测试28连接/20写许可`mixed-500-1789009747334`。读取P95 174.84ms仍通过，但写入P95 2650.03ms，流程速率98.77/s，未优于12许可版本的104.51/s，因此不采用。最终业务仍是20连接/12许可。

500用户未通过，未执行1000用户持续高频。这里的500用户每人循环“300商品读取、当前订单读取、10项草稿保存、10项提交、停顿1秒”，远高于正常浏览节奏；不等于系统不能支持500或1000人在线。
