1. 上传及独立摘要核验已完成，`images.json` 和 `verification/upload.json` 保留证据，更新补丁固定到相同已验摘要。部署前再次核对镜像引用；后续环境提升同一摘要，不重新构建或覆盖本次标签。

3. 核对 V054、共享会话/Redis、配置和连接预算。在目标集群执行三份补丁的 server-side dry-run。
4. **先更新所有 API 后端副本，等待全部就绪；再更新导出 worker；最后更新前端。** 新前端依赖新增分页与批量操作接口，不能在旧 API 尚未全部替换时提前切换。

更新补丁仅修改指定镜像引用，保留现有 Secret、ConfigMap、资源及副本数；默认 Deployment/容器名为 backend/backend、export-worker/export-worker、frontend/frontend。包内 `rollback-*.template.json` 需在发布前填入实际旧镜像，禁止直接应用占位符。

## 多副本与验证边界

沿用手动扩缩，无 HPA。默认 4 API + 1 worker 的既有常态连接预算 86，滚动额外一个 API 时 107，另留终止中 Pod、监控和 DBA 连接余量；本次未新增连接池。批量删除确认不依赖单 Pod 内存，同一镜像可跨副本确认与执行。导出 worker 继续数据库任务领取、共享存储和既有临时目录限制。

本机隔离验收使用 `order-show-ack-smoke`、独立 `ack_smoke` 数据库及本地 Redis/MinIO，不能替代真实 ACK、PolarDB、阿里云 Redis/OSS、Ingress、滚动升级及容量验收。具体通过项、条件跳过与待验范围以 `verification/` 为准。

部署资料 ZIP 不包含镜像 tar、JAR、源码包、凭据、私有会话或完整日志。两个正式镜像保留在本机 Docker；源码归档、原始日志、截图及合成会话仅保留在忽略目录 `outputs/ack-release-20261110.2/`。
