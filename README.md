# 通用订货会系统原型

面向调味品事业部订货会的多端交互原型，覆盖客户订货 H5、订货排行、专题战报、现场抽奖和运营管理后台。

> 当前版本是前端演示原型：商品 Excel 已接入浏览器端真实解析，但仍未接入后端接口、数据库、文件存储、权限系统和实时数据推送，不能直接用于正式订货会。刷新页面会恢复原型初始数据。

## 当前页面

项目通过顶部导航切换五个演示端：

| 页面 | 用途 | 当前能力 |
| --- | --- | --- |
| 订货 H5 | 经销商手机端订货 | 订货通道与综合大区选择、手机号验证、商品筛选、购物明细、订单确认和提交结果 |
| 订货排行 | 现场大屏 | 下拉选择特渠或综合区域、公司订单金额 TOP90、分公司订货金额 TOP30 |
| 专题战报 | 现场大屏 | 九类战报切换、TOP5、总战绩、区域及产品线统计 |
| 幸运抽奖 | 现场大屏 | 抽奖动画和中奖名单展示 |
| 管理后台 | 运营人员 | 商品及白名单导入预览、订单详情、抽奖规则 |

## 已实现的原型功能

### 客户订货 H5

- 首屏选择综合客户或特渠专业客户订货通道。
- 综合客户继续选择东区、南区、北1区或北2区，特渠专业客户直接进入身份验证。
- 输入白名单电话，并在验证时按标准化电话精确匹配白名单，同时核对所选客户类型和综合客户大区；不以固定号码长度作为通过条件。
- 未匹配白名单时停留在当前页提示错误，修改电话后可重新验证。
- 通道与大区选择只决定进入路径，不能覆盖白名单中的真实客户身份。
- 订货、订单确认和提交结果页面同步展示已验证的客户类型与大区。
- 支持返回上一步、重新选择通道，以及提交后返回活动首页。
- 返利产品与非返利产品切换。
- 按产品线和关键词筛选。
- 按箱增加、减少或直接输入订货数量，输入框具有明确的编辑状态。
- 实时计算已选商品数、总箱数和订单金额。
- 点击底部订货栏可以打开已选商品明细。
- 购物明细支持修改数量、删除单品、清空商品并查看单项金额。
- 确认订单页展示完整经销商名称、商品明细和订单总金额。
- 提交后进入“我的订单”页，展示订单号、状态、提交时间、商品明细和操作记录。
- 一个经销商只保留一个订单号；首次提交创建 V1，后续每次成功修改并重新提交生成新版本，订单号不变，仅更新当前内容和最后提交时间。
- 截止时间前支持修改订单；商品全部删除后可确认“取消本次订货”，订单状态变为“已撤回”，重新提交后恢复为“已提交”。
- 取消本次订货不会生成空版本，保留最近一次非空提交的商品、金额和订单号；取消作为操作记录保存，不计入有效订单、金额统计和抽奖资格。
- 截止后订单只能查看，不能修改、取消或重新提交。
- 底部订货栏采用吸附布局，不遮挡商品。
- 礼盒只是商品属性标记，不作为独立产品线参与筛选。
- 使用虚拟商品图片，后续可替换为正式商品图。

### 商品管理

- 浏览器端读取一个统一商品 Excel，并按 4 个 Sheet 自动确定客户类型和返利状态：`综合参与返利`、`综合不参与返利`、`特渠参与返利`、`特渠不参与返利`。
- 解析结果只保存在当前页面内；确认导入后追加到当前商品目录，不写入数据库。
- 支持在商品 Excel 后选择商品图片 ZIP；浏览器端解压图片并按物料名称标准化匹配，不涉及物料代码。
- 支持按客户类型、返利状态筛选导入预览。
- 支持按物料代码或物料名称模糊搜索，搜索与客户类型、返利状态筛选同时生效。
- 展示序号、客户类型、返利状态、产品大类、产品线、物料代码、物料名称、商品图片、品牌、品种、规格、箱规、元/瓶、元/箱、吨箱转换系数、礼盒标记、分公司限制和状态等字段。
- “是否礼盒”直接读取 Excel 的“是否为标品礼盒”字段；不再根据商品名称判断。
- “分公司定制品”用于限制商品只有白名单所属分公司的经销商可以下单，空值表示全部分公司可下单。
- 导入前检查缺少 Sheet、缺少表头、空物料代码和同一 Sheet 内重复物料代码；异常行可编辑或删除后再确认。
- 当前商品原型采用“追加 + 去重 + 更新”：物料代码按客户类型和返利状态优先识别；缺少物料代码时按物料名称、规格和箱规匹配；匹配到已有商品则更新，不重复新增。同一物料代码在不同客户类型或返利 Sheet 中可以分别存在。
- 支持手动编辑、单个删除、全选当前页删除和选择全部筛选结果删除；已导入目录还可单独删除“全部导入商品”，手动添加的商品会保留。删除商品只从当前可下单目录移除，已有订单保留商品快照和金额。
- 删除商品不等于删除订单：正式系统中已被订单引用的商品不能物理删除，应标记为停用或逻辑删除；商品从新订单中隐藏，但历史订单继续展示下单时的商品名称、规格、价格、数量和金额。
- 缺少关键字段的商品标记为“待完善”，不会进入 H5 可下单商品列表。
- 图片匹配支持标准化名称完全匹配、名称包含匹配和安全的唯一模糊匹配；多个候选时标记为“待确认”，未匹配商品使用默认占位图。
- 商品图片只保存在当前页面内；确认导入后商品行保存主图和图片列表，H5 使用主图，刷新页面后恢复初始数据。
- 后台商品图片字段和 H5 商品主图支持点击打开预览；预览支持放大/还原、左右切换、缩略图选择、Esc 关闭，手机端支持左右滑动浏览多图。
- 商品编辑和手动添加支持直接上传图片；可追加多张、替换全部、删除单张和设置主图。手动图片标记为“手动维护”，优先于 ZIP 匹配，单张不超过 10MB。
- 商品列表默认每页 50 条；筛选后回到第 1 页，按 Sheet 顺序和 Excel 源序号稳定排序，页面展示序号连续计算。
- 支持手动添加商品，序号按客户类型和返利状态分组自动生成。
- 礼盒标记用于商品展示和统计，不能替代产品线字段。

### 白名单管理

- 浏览器端真实读取一个白名单 Excel，按“综合客户白名单”和“特渠客户白名单”两个 Sheet 自动确定客户类型，其他 Sheet 自动忽略。
- 当前实际文件解析得到综合客户 1,073 名、特渠专业客户 607 名；Sheet 外的说明行会自动跳过。
- 支持按综合客户、特渠专业客户筛选。
- 支持按经销商名称（简/全）、经销商姓名或经销商电话模糊搜索，搜索与客户类型筛选同时生效。
- 展示序号、客户类型、大区、分公司名称、经销商名称（简）、经销商名称（全）、经销商类型、经销商姓名、经销商电话、分公司确认人姓名和电话。
- 白名单采用“首次真实导入替换演示数据、后续 Excel 追加导入”的方式；导入结果只保存在内存，刷新页面恢复初始数据。
- 追加导入按“客户类型 + 标准化经销商名称全称”匹配客户；匹配到后覆盖最新资料，电话变化会更新原客户，不会因为电话变化重复新增。
- 同一客户类型下名称重复或缺少名称全称会标记为待处理；电话为空、格式异常或同客户类型内重复时保留已有有效电话并提示处理。综合和特渠可以存在同一个手机号，并分别进入对应通道。
- 导入预览展示新增、电话更新、信息更新、未变更和异常状态，支持编辑、单个删除和勾选批量删除，确认后才写入当前白名单。
- 删除白名单只影响后续登录和下单；正式系统中已被订单引用的客户应保留客户快照或逻辑删除，历史订单继续展示下单时的经销商信息。
- 白名单支持删除单个、批量删除、删除全部导入白名单，以及“清空全部白名单”；清空全部会同时删除 Excel 导入和手动添加的数据，执行前必须二次确认。
- H5 先选择综合或特渠通道，再按所选客户类型和手机号匹配对应经销商信息。
- 白名单列表默认每页 50 条；筛选后回到第 1 页，综合和特渠按 Sheet 顺序排序，页面展示序号连续计算；批量选择默认只作用于当前页。
- 支持手动添加白名单，序号按客户类型分组自动生成。
- 管理后台白名单列表和编辑表单完整展示经销商电话、分公司确认人电话，便于核对客户身份；H5 与订单页面仍按权限脱敏展示电话。
- 当前原型的删除只修改前端内存，刷新页面后恢复初始数据；正式系统删除商品或白名单时由后端同步处理。

### 现场到场客户管理

- 管理后台新增“现场到场”页面，默认加载 `现场到场客户名单-演示.xlsx` 的演示数据，用于展示真实导入后的页面效果。
- 页面保留真实 `.xlsx/.xls` 上传入口；当前页面展示经销商姓名、联系电话、分公司、经销商名称和客户类型，字段缺失时留空，不因缺少字段阻断导入。
- 支持按客户类型、分公司和关键词搜索，默认每页 50 条；演示数据明确标记为“演示数据”，可一键恢复。
- 支持手动添加和编辑现场到场客户，手动添加时序号自动生成；当前不强制字段格式和重复校验。
- 当前页面只作为到场客户管理入口，尚未将数据接入抽奖候选池；后续补充手机号或其他唯一标识后，再做白名单匹配和抽奖资格计算。

### 订单管理

- 查看订单列表。
- 按“全部订单、已提交、已撤回”及客户类型“全部、综合、特渠”筛选订单。
- 仅按经销商名称或经销商电话搜索，不搜索订单号；列表和详情中的电话默认脱敏展示。
- 点击订单行打开订单详情。
- 查看商品明细、订单金额、箱数和吨数。
- 展示创建、首次提交、最后修改、撤回时间和编辑权限。
- 已撤回订单仍保留商品明细、金额和订单号，不显示为空订单。
- 订单详情展示当前快照、版本记录和操作记录，支持查看每次提交的金额、商品变化和操作人。
- 当前版本商品明细固定展示在详情上方；历史版本按版本号查看完整商品快照，不与当前明细重复展开。
- 展示提交、修改、撤回和重新提交等操作记录。
- 支持在可修改订单上撤回订单并二次确认，后台撤回需填写原因，截止后订单仅可查看。
- 操作记录按最新时间倒序展示；撤回是订单操作，不新增版本。

### 看板、抽奖与主题

- 订货排行通过下拉筛选器切换五个渠道或区域，不在页面中常驻展示全部选项。
- 专题战报支持九类内容切换；当前看板筛选器名称保持不变，综合客户和特渠专业客户 TOP 榜不显示金额。
- 专题战报总战绩与产品线统计使用“特渠专业客户+综合客户”“礼盒”“综合客户”等最终口径，去除重复的实时汇聚说明。
- 抽奖后台支持新增、复制、删除和发布轮次，并配置奖品、中奖人数、客户类型和资格截止时间。
- 候选范围支持所有活动客户、现场到场客户和有效下单客户三种互斥模式。
- 最低订单金额仅在“有效下单客户”模式中显示，填写 `0` 表示不限制订单金额。
- 支持到场名单导入反馈、候选人数统计、排除原因和候选名单预览。
- 后台配置与现场抽奖页使用同一份前端状态联动；当前仍未接后端，刷新页面后恢复初始 Mock 数据。
- 现场抽奖页负责选择已发布轮次、确认规则、执行动画和展示结果。
- 现场抽奖页只保留必要的轮次和候选人数信息；按钮按状态显示“开始抽奖”“停止并揭晓”“完成本轮抽奖”。
- H5、数据看板和抽奖页背景均支持自定义图片上传预览。

## 本地运行

### 环境要求

- Node.js `>= 22.13.0`
- npm

### 安装与启动

```bash
npm install
npm run dev
```

启动后访问终端显示的本地地址，通常为：

```text
http://localhost:3000/
```

### 构建与测试

```bash
npm run build
npm test
```

`npm test` 会先执行生产构建，再检查页面服务端渲染和关键资源。

### 商品 Excel 与图片处理方案（待实现）

当前原型中的 Excel 解析、图片 ZIP 解压和图片匹配均在浏览器端完成，结果只保存在当前页面状态中；图片匹配本质上是图片文件名与商品名称的标准化匹配，不是 AI 识图。

正式开发后，处理流程规划如下：

1. 前端上传商品 Excel 和图片 ZIP，后端负责接收、解析和校验。
2. 后端按商品名称标准化规则匹配图片文件名；唯一匹配成功的图片进入导入结果，多个候选标记为“待确认”，未匹配图片不直接关联商品。
3. 确认导入后，商品字段和导入批次写入数据库，图片文件写入对象存储；数据库只保存图片与商品的关联信息、存储键、主图标记、排序和来源等元数据。
4. 删除或替换商品图片时，由后端同时删除或更新数据库关联记录和对象存储文件。对象存储不会因为数据库记录被删除而自动删除文件，因此需要后端处理失败重试和遗留文件清理。
5. 如果图片仍被历史订单快照或其他商品引用，不能直接物理删除，应保留文件或先建立独立的历史快照。

开发环境可以先使用服务器本地图片目录；正式环境建议使用对象存储，以便进行备份、扩容和多实例部署。

完整规划见 [PROJECT.md](./PROJECT.md)。

## 数据安全提示

不要将真实客户手机号、正式订单或中奖名单写入前端源码。正式数据必须保存在受权限控制的后端和数据库中。

测试环境与正式环境应使用不同的域名、后端、数据库、对象存储和配置。正式启用时应重新导入审核后的商品与白名单，不应将测试数据库直接转换为正式数据库。
