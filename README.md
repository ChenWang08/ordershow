## 当前实现

以下为功能说明；最新部署状态见文首部署摘要，历次部署详情见文末记录链接。

- H5 身份切换：返回活动首页时将旧客户草稿写入本机浏览器并清理身份、手机号及页面数据，不等待后台草稿请求。浏览器存储不可用时以本页内存暂存并提示丢失风险，切换仍可继续；重新验证后只恢复本活动、本客户且基准仍有效的草稿。单一客户类型和不区分类型活动保留直接验证入口。

- 展示页面顶部栏：订单看板、订货排行、专题战报、幸运抽奖支持默认隐藏及整条顶部悬停展开；使用鼠标不显示箭头，展开推开内容、收起释放空间。管理平台和正式 H5 保持原样。

- 重新开放订货：在“活动概览 → 活动设置”中，对手动或自动截止、整场已结束的活动点击“重新开放订货”，填写两个新时间和原因并二次确认。仅超级管理员和本部门管理员可操作；必须满足服务器当前时间 < 订货截止时间 < 整场活动结束时间，同部门活动时间不能冲突。恢复后沿用原活动与入口，保留订单、待审核申请和中奖记录，恢复实时统计；已失效的客户登录需重新验证。详见 [功能说明](docs/deployment/2026-10-14-activity-reopen.md)。

- 活动背景：管理员在“活动概览 → 页面背景设置”配置两项背景，每场活动独立保存，上传成功即保存，支持预览、替换和恢复默认。H5 背景仅用于通道选择、大区选择和身份验证页；电脑端背景由订单排行、专题战报、幸运抽奖共用，不包含订单综合看板。支持 JPG/JPEG、PNG、WebP，H5 上限 5 MB、电脑端上限 10 MB（按 1024 × 1024 字节计）；推荐尺寸分别为 750 × 1500、1920 × 1080 px，推荐尺寸不是强制要求。当前按原文件保存，未实现自动压缩。
- 背景显示：图片等比例居中铺满，不拉伸，屏幕比例不同可能裁切边缘。未配置、恢复默认或图片加载失败时，H5 使用 `public/order-entry-backdrop.svg`，三个电脑页面恢复各自原有默认背景。自定义电脑背景加载成功后隐藏原来的月亮、云、山峦及战报背景叠层。重要文字与二维码应由页面单独展示，图片边缘预留裁切空间。
- H5 电脑端约定：继续保持独立 H5 页面随浏览器宽度铺满，宽屏下卡片和按钮会变宽；不增加 430～480 px 最大宽度或居中手机框。手机端继续全屏适配。此约定不改变三个电脑展示页面的布局。

- 活动直播间：管理员在活动概览配置 HTTPS 直播间完整链接，配置后 H5 显示“退出”入口并返回该直播间，清空配置后隐藏；活动资料通过 SSE 同步。退出前将购物车草稿写入本机浏览器，待审核中的继续修改也适用；本机保存失败或提交结果尚待确认时先提示确认，返回直播间不会取消订单提交。数据库迁移 V038 新增活动直播间字段。
- Excel 模板下载：商品导入、白名单和现场到场页面分别提供对应模板。下载后删除示例数据、保留表头并填写实际信息，再上传预览并确认导入。
- H5 手机适配：活动独立订货页全屏展示，适配安全区域、浏览器可视高度和软键盘；商品内容区滚动，底部购物车操作栏保留，窄屏下商品和购物车操作区域自动换行。数量输入支持六位数字、聚焦全选和暂时清空；清空期间保留原数量及购物车行，失焦时按 0 处理，输入上限为 999999。

- 导入文件提示：商品 Excel、商品图片 ZIP、白名单 Excel、现场到场 Excel 未选择时显示对应的“尚未选择…文件”，ZIP 标注选填，不再显示固定示例文件名。选中/替换后显示真实文件名，解析失败仍保留本次文件名及错误；移除后恢复对应空状态，活动切换和后端预览恢复沿用原有状态隔离。

- 商品完整性：前端 Excel 预览、后端解析/重校验/发布和手动维护统一只检查元/箱、吨箱转换系数是否为有效正数。数据状态自动计算，不再人工选择有效/待完善；待核对问题仍优先拦截。无效数值在新保存时按缺失处理，已有数据修正只改状态和预览统计，不改变商品资料、订单或自动发布批次。

- 侧栏防误关闭：新建活动、商品、白名单、现场到场、订单创建/调整、订单审核、订单详情、抽奖候选池八类右侧侧栏，点击灰色背景均不关闭。表单主动关闭时仅在业务内容与打开时不同的情况下确认放弃，保存/审核期间禁止关闭；只读侧栏直接关闭。订单审核切换查看完整原订单也保护未提交备注。
- 后台订单选品：新增订单集中展示“已添加商品”，商品列表与已添加区共用数量；填写正整数自动加入，改为 0 移除，不设置独立添加/移除按钮。暂时清空数量时保留正在编辑的行，失焦后按 0 处理。调整订单保留原商品与新增商品分区，原商品为 0 时标记保存后移除。数量控件支持完整显示六位数字，保留左右加减、取消原生数字箭头，并适配窄屏。更换客户有选品时确认清空；服务端试算、版本校验及保存规则不变。

- H5 提交重试：同一次提交在网络异常、超时、503 后复用原幂等键和请求体，刷新后可恢复 24 小时内的待确认请求；后端保存首次订单版本响应快照，并按唯一约束、规范化指纹和事务处理并发。新快照记录在满足活动结束及成功提交后 30 天保留期后分批清理。详见 [实现与测试说明](docs/testing/h5-idempotency-retry.md)。

- H5：按当前已发布的有效白名单决定入口：仅综合客户或仅特渠专业客户时直接验证手机号并标注对应类型，综合客户的大区由后端从白名单自动识别；双类型时保留通道选择，综合客户按现有规则选择具体大区或“不分大区”。无有效白名单时显示“暂无可验证客户”。当前白名单客户类型全部为空时隐藏通道和大区选择，直接输入手机号验证，并读取全部适用商品。商品目录同时存在参与和不参与返利商品时显示“返利产品/非返利产品”页签，否则显示“全部商品”；返利字段为空的商品属于通用商品，在全部商品或两个返利筛选中均可见。产品说明过长时在商品卡片说明区内部滚动，价格和数量控件保持可操作。商品目录按项目组分组；确认页和已提交订单在总金额下展示各项目组小计。验证成功后可首次提交订单；首次提交、仅增加数量或新增商品直接生效；有效订单减少任一商品数量、删除商品或整单撤回时，整次变更需审核，审核前原订单不变。已撤回或已作废订单在订货截止前重新提交时直接恢复，不与失效前数量比较，沿用原订单号并保留历史。商品和数量完全未变时不更新订单或创建申请。未提交购物车按“活动 ID + 活动客户 ID”自动保存到后端，同一客户刷新、关闭后重新验证或更换设备可恢复，不同客户互不读取。
- 商品：统一 Excel 单个非空 Sheet 预览（Sheet 名称不限）、异常行编辑/删除、原子全量替换和手动维护；判重先按客户类型、返利类型和标准化物料名称分组，有代码时再按标准化物料代码区分；代码相同拦截、不同允许，任一代码为空时同名拦截。物料代码可空，图片 ZIP 仍只按名称匹配且同名商品共享图片。产品说明随商品保存并在 H5 商品详情展示。图片待确认时，后台商品列表的图片列显示候选图片数量数字。

## 超级管理员忘记密码：服务器重置

首次初始化仍使用 `.env` 的初始密码，首次登录仍必须改密。忘记密码时，有服务器/Docker 操作权限的人可执行下面的维护命令，自动定位唯一超级管理员；没有或异常存在多个超级管理员时拒绝执行。

本机 PowerShell（在项目目录运行）：

```powershell
.\scripts\reset-super-admin-password.ps1
```

Linux 服务器（在部署目录运行）：

```sh
sh scripts/reset-super-admin-password.sh
```

脚本显示 Compose 文件和服务，命令随后显示实际数据库名称、数据库服务器及超级管理员用户名/状态。核对环境后，按提示输入 `数据库名/用户名` 确认，再明文输入两次新密码，输入字符会直接显示在终端。程序不会额外复述密码，也不写入应用日志或数据库审计；终端显示、截图、录屏及终端录制可能保留明文。密码遵循现有 8～100 字符规则，同时受 BCrypt 72 UTF-8 字节上限约束，不允许全空白或与当前密码相同。不要将新密码写在参数、环境变量、管道或脚本中。必须使用交互终端，不要给 `docker compose exec` 加 `-T`。

可显式指定部署配置：PowerShell 使用 `-ComposeFile <文件> -Service <服务>`；Linux 使用 `sh scripts/reset-super-admin-password.sh <compose文件> <服务>`。例如隔离测试环境服务为 `backend-test`，配置为 `docker-compose.test.yml`。维护进程使用目标容器现有的 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`，不读取或修改本地其他环境。

成功后，新密码直接使用，不再要求改密；全部旧登录会话失效，账号启停状态不变，`.env` 不会自动更新。原密码哈希、会话撤销及 `ADMIN_PASSWORD_SERVER_RESET` 审计记录在同一 MySQL 事务中提交。命令仅在提交成功后报告成功；数据库或提交结果异常时报告“未确认重置成功”，不要假定旧凭证已失效，恢复连接后核对新密码登录与审计记录再重试。已经成功但终端未收到结果时，用相同密码重试会提示与当前密码相同，可用该密码登录核实，或再次设置另一个新密码。

功能首次交付需更新后端镜像；以后执行重置只启动短暂维护进程，不重启业务服务、不执行数据库迁移、不依赖邮件、短信或 Redis，也不提供公开重置 API。已通过认证的在途请求可能继续完成，重置提交后发起的新请求必须重新登录。认证检查和测试说明见 [服务器密码重置验证](docs/testing/server-password-reset-2026-10-09.md)。

## 成员账号使用

超级管理员或部门管理员登录后进入左侧“成员管理”。超级管理员新增成员时选择部门，部门管理员新增成员自动归属本部门；填写姓名、用户名、8–100 位密码并勾选六项权限。姓名允许中文、英文或混合，非空且最多 100 字符；用户名不支持中文，为 3–64 位，以英文字母或数字开头，其余允许英文字母、数字及 `_ . @ -`。

勾选模块即拥有与部门管理员一致的模块业务操作，仍受现有活动状态规则限制。活动概览权限不开放活动配置和生命周期按钮；成员不能管理账号。零权限成员登录后显示暂无功能权限。

权限保存后后续请求立即按新权限校验；当前源码在首次进入、重新聚焦或收到权限拒绝后同步身份，不再定时检查（此后台改动待部署，见文首）。停用账号或重置密码使原会话失效；后续请求确认登录失效时返回登录，重新启用后需重新登录。审核、调整、作废等操作记录实际账号，新记录保留操作时姓名与用户名，改名或停用不改变历史身份。旧共享账号记录不能还原为具体成员。

## 核心业务规则

下文“截止后客户只读”“活动结束后历史回看”均指活动尚未重新开放期间；成功重新开放后按新的订货窗口执行原有业务规则。

H5 增量直提、减量审核及撤回/作废后直接恢复的规则与验证范围见 [2026-10-10 实现说明](docs/testing/h5-increment-review-2026-10-10.md)。

- H5“我的订单”有待审核修改申请时默认展示最新申请的商品、数量和金额快照，可切换查看正式订单；待审核内容不提前标为新版本。撤回申请保留原订单明细，驳回展示正式订单及原因，截止后仅可查看。申请成功不再重复显示顶部提示。

- 订单管理提供独立“变更审核”页签，支持分页搜索及无图片的商品差异详情。申请仅有待审核、已通过、已驳回三种状态；H5 截止前可继续编辑待审核申请，新申请原子替代旧申请，旧申请以“已被客户新申请替代”驳回并保留历史。管理员调整或审核发现订单变化时自动驳回旧申请。

- 加入当前活动且物料名称有效的商品可进入 H5；项目组、规格、箱规等选填字段缺失不影响数据状态，展示沿用未分类或空值处理；仅元/箱或吨箱转换系数缺失、非有效正数时标记待完善。
- 缺少有效元/箱的商品可展示但不可下单；缺少吨箱转换系数仍可下单，订单总吨数累加可计算明细，无法计算的明细按 0 计入。
- 客户只能在订货截止前首次提交、直接增加订货、恢复失效订单或创建减量/撤回申请；截止前已创建的申请不会自动过期，管理员仍可按权限审核和维护订单，截止后客户侧只读。
- 时间调整：订货中可提前或延后两个结束时间，须满足服务器当前时间 < 订货截止时间 < 整场活动结束时间；订货开始时间保持不变。草稿和待开始活动沿用创建、发布流程，整场结束时间同样须严格晚于订货截止时间。
- 截止或结束后必须明确点击“重新开放订货”才能恢复；普通保存不会恢复订货。订货已截止后的“延长整场活动时间”继续保持订货关闭，不提供独立的“仅恢复活动”选项。操作校验管理员权限、所属部门和活动版本，并记录原因及变更前后状态、时间。
- 活动采用两层结束机制：订货截止只关闭 H5 下单；整场活动结束关闭抽奖，统计进入历史回看。独立活动资料 SSE 在整场结束后仍可连接，以接收重新开放通知。结束后的排行与战报使用最终展示快照，后台订单维护后自动更新该快照，页面手动刷新获取。重新开放时清除旧最终快照，手动查询当前统计，再次结束时按最新订单生成最终看板与战报；已完成抽奖轮次和中奖记录不重置，订单减量/撤回审核规则不变。
- 未提交购物车只保存在本机浏览器，不创建正式订单、订单号或订单版本，不调用后台草稿接口。草稿按活动/客户隔离，基于当前正式订单及申请恢复；订单 ID、业务/锁版本、状态或申请变化时失效。成功提交或创建申请后清除，保存最多 7 天且不超过订货截止时间，截止/结束后不恢复。旧后台草稿不迁移。
- 本机草稿保存毫秒时间戳，不通过 API 传输；其他业务时间沿用 UTC 保存及传输。草稿恢复提示固定按 `Asia/Shanghai`（UTC+8）展示。
- 客户在订货截止后只能查看订单；后台管理员在活动开始后（含截止和结束）仍可新增、调整和逻辑作废订单，订单变化会反映到看板、排行和战报。超级管理员可在活动设置底部手动归档已结束活动、解除归档或永久删除草稿/已结束/已归档活动；原活动菜单提供归档筛选和删除进度，不增加侧边栏。归档后按原部门和功能权限查看、导出，全部业务写入冻结；解除归档恢复已结束，不自动开放下单。永久删除无自动备份、无回收站，确认后立即隐藏并拒绝访问，后台限量分批清理、断点续跑和失败重试，最终保留独立删除凭证。实现需先应用 V051 迁移；本轮仅验证相关模块，未部署业务应用。
- 白名单、到场管理和订单管理页可向已登录管理员显示完整电话；H5、排行、战报、抽奖大屏和日志不得显示手机号明文。
- 商品、白名单和到场名单均以最近一次发布的完整文件为准；当前页面不提供停用/恢复功能。单条删除后从当前列表消失，底层仅为保护历史订单和审计保留不可见记录。
- 商品、白名单和现场到场 Excel 均为全量替换；当前业务只读取最近发布版本，旧版本仅供审计。
- 每次商品 Excel 与本次图片 ZIP 构成独立待发布批次，不比较上一商品版本，也不继承上一版本图片；上传仅用于预览，确认且全部保存成功后才切换当前版本。预览图片关系按商品行隔离，删除或排除一张图片不会改写其他不同商品。商品状态为“有效 / 待核对 / 待完善”，并可按“价格有效 / 价格待完善”单独筛选；图片状态为“已匹配 / 待确认 / 未匹配”。
- H5 商品返利页签按当前商品目录动态生成：只有同时存在“参与”和“不参与”两种明确返利状态时显示两个页签，否则显示“全部商品”；返利为空的商品按通用商品处理。商品说明区域独立滚动，不能挤走价格和数量控件；后台图片列对“待确认”只显示候选图片数量数字。
- H5 商品目录按项目组分组；购物明细、确认页和已提交订单也按项目组分组并显示项目组。目录卡片最小高度为 140 CSS px，随内容适配，图片区为 96 × 120 CSS px，图片按比例完整显示。H5 图片预览弹窗保持 55% 高度，按图片原始尺寸和预览区实际尺寸完整适配；支持放大后滚动查看，多图仅在未放大时左右切换。
- 每次白名单 Excel 也是独立的完整名单，上传仅生成预览，确认后才全量替换；页面状态只显示“有效 / 待处理”，不展示新增、更新或移除等跨版本差异。
- 到场名单每次发布都清除上一版本的当前关联语义，并对当前完整白名单重新关联；白名单重新发布时也自动重算当前到场关联。
- 抽奖结果由后端生成并先保存，前端动画不参与随机计算；现场到场候选必须处于“已关联”状态并指向当前有效白名单，按活动客户 ID 去重。

## 当前实现与生产规划边界

当前仓库已经实现可完整本地运行的单体版本：统一 React 前端、一个 Spring Boot 后端进程，以及由 Docker Compose 管理的 MySQL、Redis 和 MinIO。导入任务和 Flyway 迁移当前随本地后端运行方式执行。

独立 Background Worker、独立 Migration Job、多 API 实例、托管 LB/WAF/CDN、正式监控告警和云端高可用属于生产部署目标，尚不能视为当前本地环境已经完成。
