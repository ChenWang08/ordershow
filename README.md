# 订购会业务系统

本机后端已于 2026-09-10 更新到H5高频写入隔离版本，部署范围、镜像标识和验证结果见 [最新本地部署记录](docs/deployment/2026-09-10-high-frequency.md)。此前记录：[启动/审计及订单号修复](docs/deployment/2026-09-08-startup-audit.md)、[H5吞吐优化](docs/deployment/2026-09-08-h5-throughput.md)、[实时通知优化](docs/deployment/2026-09-08-realtime.md)、[性能优化部署](docs/deployment/2026-09-08-performance.md)、[六阶段重构部署](docs/deployment/2026-09-07-refactor.md)。

面向调味品事业部订购会的完整本地业务系统。项目保留已确认的 React UI，并已接入 Spring Boot、MySQL、Redis、MinIO、Excel/ZIP 导入、H5 订单、后台订单管理、实时排行、专题战报、抽奖和审计日志。

## 当前实现

- H5：当前白名单有客户类型时按综合/特渠验证手机号，并按综合客户白名单动态处理大区；综合客户可选具体大区或“不分大区”，特渠不要求综合大区。当前白名单客户类型全部为空时隐藏通道和大区选择，直接输入手机号验证，并读取全部适用商品。商品目录同时存在参与和不参与返利商品时显示“返利产品/非返利产品”页签，否则显示“全部商品”；返利字段为空的商品属于通用商品，在全部商品或两个返利筛选中均可见。产品说明过长时在商品卡片说明区内部滚动，价格和数量控件保持可操作。商品目录按产线分组；确认页和已提交订单在总金额下展示各产线小计。验证成功后可提交、修改、撤回和重新提交订单；每次非空提交生成不可变版本。未提交购物车按“活动 ID + 活动客户 ID”自动保存到后端，同一客户刷新、关闭后重新验证或更换设备可恢复，不同客户互不读取。
- 商品：统一 Excel 单个非空 Sheet 预览（Sheet 名称不限）、异常行编辑/删除、原子全量替换和手动维护；判重先按客户类型、返利类型和标准化物料名称分组，有代码时再按标准化物料代码区分；代码相同拦截、不同允许，任一代码为空时同名拦截。物料代码可空，图片 ZIP 仍只按名称匹配且同名商品共享图片。产品说明随商品保存并在 H5 商品详情展示。图片待确认时，后台商品列表的图片列显示候选图片数量数字。
- 客户：白名单 Excel 使用一个非空 Sheet，Sheet 名称不限；首列为客户类型，可全量填写综合/特渠或全量留空；同一客户类型内手机号唯一，综合/特渠之间允许同手机号；按客户类型 + 经销商全称 + 所属分公司判重，空客户类型时按经销商全称 + 所属分公司判重；手机号按要求明文保存，登录后的白名单、到场和订单管理页显示完整电话，H5 和公开页面仍脱敏；支持当前版本单条维护和删除。
- 到场：现场名单 Excel 每次全量替换；发布时在参会人员类型内按手机号、经销商全称、同分公司经销商简称依次精确匹配当前白名单，展示已关联、待确认、未关联状态，也支持单条补录；登录后的到场管理页显示完整电话。
- 多活动后台：超级管理员可一次创建部门及其共享后台账号（部门编号自动生成，账号显示名自动使用部门名称，登录密码由超级管理员统一设置和重置），并在活动概览顶部切换全部活动；部门账号只显示和操作本部门活动，也可新建独立草稿活动；订货截止与整场活动结束分开控制，新活动不复制白名单、订单或历史结果。
- 后台订单：支持分页列表、详情、商品快照、版本、操作轨迹、搜索、筛选和多工作表 Excel 导出；活动开始后，超级管理员及本部门管理员可新增、调整和逻辑作废订单，全部操作保留来源、原因和审计记录。
- 商品价格：管理员保存基础箱价或阶梯优惠后，当前活动的已提交订单自动更新当前成交价、小计和订单总额；不新增订单版本或订单操作记录，历史版本保留原提交价格。
- 看板：活动概览、订单综合看板、有效订单排行和专题战报均读取真实订单；整场活动结束前使用 SSE 变更通知，结束后停止实时推送并进入“历史回看”，管理员新增、调整或作废订单时自动刷新最终展示快照，无需运营人员手工重新生成；撤回和作废订单不计入统计。排行累计吨数汇总有效订单当前明细中已成功折算的 `line_tons`，部分商品缺少每吨箱数时仍展示其余明细的可计算吨数，全部不可折算时显示“待完善”。排行支持“全部客户”筛选，统计综合、特渠及系统内代表空客户类型的 `ALL` 订单。白名单客户类型全部为空时，活动概览保留“全部客户/综合客户/特渠专业客户”三行，其中综合和特渠为 0；订单看板按全量客户汇总，订单额占比位置显示“全部客户 100%”环形图并隐藏渠道、片区拆分，排行正常展示全部客户数据，专题战报保留入口但显示“暂不展示”占位。
- 抽奖：订货截止后仍可继续；整场活动结束后停止抽奖和重抽，只读展示已保存结果。规则和轮次配置、候选资格校验、Redis/数据库防重、候选快照、后端随机、结果先持久化再播放动画、完成和重抽均留痕。
- 安全：管理员会话、H5 会话、CSRF、幂等键、手机号 HMAC 检索、导入预览敏感载荷加密及自动审计日志。

本地源数据包含 233 条可见商品（229 条可订）、1,647 名有效白名单客户和 121 条到场记录。按当前精确规则复算后，108 条已关联并具备“现场到场客户”抽奖资格，3 条因手机号与名称冲突待确认，10 条未关联；另有 190 个唯一图片文件。实际运行结果以最近一次发布版本为准，源 Excel/ZIP 不进入 Git。

## 一键启动

前置条件：Docker Desktop 已启动。Java 和 Maven 仅在脱离 Docker 调试后端时需要；正常本地运行不需要额外安装 MySQL、Redis、MinIO 或 Maven。

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
```

访问地址：

- 前端：http://localhost:3000
- H5 下单（活动专属）：http://localhost:3000/h5/2026-mid-autumn
- 管理后台：http://localhost:3000/admin
- 订单看板：http://localhost:3000/screen/2026-mid-autumn/dashboard
- 排行大屏：http://localhost:3000/screen/2026-mid-autumn/ranking
- 专题战报：http://localhost:3000/screen/2026-mid-autumn/report
- 抽奖大屏：http://localhost:3000/screen/2026-mid-autumn/lottery
- 后端健康检查：http://localhost:8080/api/v1/actuator/health
- MinIO 控制台：http://localhost:9001

订单看板的模块、统计口径、交互和验收规则见 [`docs/design/06-order-dashboard-plan.md`](docs/design/06-order-dashboard-plan.md)。

客户正式访问活动专属 `/h5/{活动编号}`，看板和抽奖使用 `/screen/{活动编号}/...`；旧 `/h5` 入口仅在单活动兼容场景下自动定位，多部门活动同时运行时会提示改用专属链接，避免订单归错活动。管理后台统一访问 `/admin`，登录后通过顶部选择器切换或新建活动，并在当前浏览器记住上一次选择。旧的 `/admin/{活动编号}` 保留兼容。活动编号由后端自动生成并立即保存，但订单等业务数据始终通过内部活动 ID 隔离。

首次启动的超级管理员账号由 `.env` 中 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 决定，默认是 `admin / ChangeMe123!`。超级管理员首次登录必须修改密码；部门共享账号的登录密码由超级管理员设置，部门账号不能自行修改。正式部署前必须替换默认密码和密钥，再由超级管理员创建部门共享账号。

停止服务：

```powershell
docker compose down
```

该命令保留数据库和文件卷。只有明确需要清空全部本地数据时才使用 `docker compose down -v`。

## 开发与测试

### 商品调价与订单同步

商品基础价格或阶梯优惠保存后，自动更新当前活动相关已提交订单的当前成交价、小计和总额。无需预览确认或手动同步，不新增订单版本或调价操作记录。旧版本数据保留，当前订单详情和编辑页直接读取 order_item。

数量、吨数、其他商品、撤回和作废订单保持不变。商品和订单在同一事务内保存，失败整体回滚。看板、H5、排行、战报和当前订单导出读取最新金额；普通资料修改不触发同步。

一次性补处理使用 PRICE_SYNC_BACKFILL_ACTIVITY_ID 指定正在进行的活动，默认不执行。部署补处理后移除此配置。V024 历史批次表保留，但新的自动计价不再写入。

## 核心业务规则

- 加入当前活动且物料名称有效的商品可进入 H5；缺少可选字段时隐藏该字段并标记待完善。
- 缺少有效元/箱的商品可展示但不可下单；缺少吨箱转换系数仍可下单，订单总吨数整体留空。
- 客户只能在订货截止前自行提交、修改、撤回或重新提交；截止后客户侧只读，管理员仍可按权限维护订单。
- 活动采用两层结束机制：订货截止只关闭 H5 下单；整场活动结束才关闭抽奖和实时推送。结束后的排行与战报进入历史回看，后台订单维护后自动更新最终展示快照，不需要手工重新生成。
- 未提交购物车是独立草稿，不创建正式订单、订单号或订单版本；草稿按活动和活动客户隔离，以当前订单版本为基线，正式提交或撤回后自动清除，活动结束后失效。
- 草稿及其他业务时间以 UTC 保存和通过 API 传输；草稿恢复提示固定按 `Asia/Shanghai`（UTC+8）展示，不依赖终端系统时区。
- 客户在订货截止后只能查看订单；后台管理员在活动开始后（含截止和结束）仍可新增、调整和逻辑作废订单，订单变化会反映到看板、排行和战报。当前不提供活动归档入口；数据库保留的 `ARCHIVED` 仅作兼容状态，不作为正常业务流程。
- 白名单、到场管理和订单管理页可向已登录管理员显示完整电话；H5、排行、战报、抽奖大屏和日志不得显示手机号明文。
- 商品、白名单和到场名单均以最近一次发布的完整文件为准；当前页面不提供停用/恢复功能。单条删除后从当前列表消失，底层仅为保护历史订单和审计保留不可见记录。
- 商品、白名单和现场到场 Excel 均为全量替换；当前业务只读取最近发布版本，旧版本仅供审计。
- 每次商品 Excel 与本次图片 ZIP 构成独立待发布批次，不比较上一商品版本，也不继承上一版本图片；上传仅用于预览，确认且全部保存成功后才切换当前版本。预览图片关系按商品行隔离，删除或排除一张图片不会改写其他不同商品。商品状态为“有效 / 待核对 / 待完善”，并可按“价格有效 / 价格待完善”单独筛选；图片状态为“已匹配 / 待确认 / 未匹配”。
- H5 商品返利页签按当前商品目录动态生成：只有同时存在“参与”和“不参与”两种明确返利状态时显示两个页签，否则显示“全部商品”；返利为空的商品按通用商品处理。商品说明区域独立滚动，不能挤走价格和数量控件；后台图片列对“待确认”只显示候选图片数量数字。
- H5 商品目录按产线分组；购物明细、确认页和已提交订单也按产线分组并显示商品产线。目录卡片统一高 140 CSS px，图片区为 96 × 120 CSS px，图片按比例完整显示。H5 图片预览弹窗保持 55% 高度，按图片原始尺寸和预览区实际尺寸完整适配；支持放大后滚动查看，多图仅在未放大时左右切换。
- 每次白名单 Excel 也是独立的完整名单，上传仅生成预览，确认后才全量替换；页面状态只显示“有效 / 待处理”，不展示新增、更新或移除等跨版本差异。
- 到场名单每次发布都清除上一版本的当前关联语义，并对当前完整白名单重新关联；白名单重新发布时也自动重算当前到场关联。
- 抽奖结果由后端生成并先保存，前端动画不参与随机计算；现场到场候选必须处于“已关联”状态并指向当前有效白名单，按活动客户 ID 去重。

## 当前实现与生产规划边界

当前仓库已经实现可完整本地运行的单体版本：统一 React 前端、一个 Spring Boot 后端进程，以及由 Docker Compose 管理的 MySQL、Redis 和 MinIO。导入任务和 Flyway 迁移当前随本地后端运行方式执行。

独立 Background Worker、独立 Migration Job、多 API 实例、托管 LB/WAF/CDN、正式监控告警和云端高可用属于生产部署目标，尚不能视为当前本地环境已经完成。
